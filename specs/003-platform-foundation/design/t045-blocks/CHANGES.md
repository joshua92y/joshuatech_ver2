### 지적에 없던 것(내가 추가로 고친 것)

1. **정지점 입력 에코** — 반환값을 받지 않는 `Read-Host` 가 입력을 성공 스트림으로 되출력하는 문제(PS-05 가 부가로 언급)를 `$stop`/`$ask` 가 값을 받아 처리하는 구조로 일괄 제거.
2. **DR1 매니페스트를 YAML 히어스트링 → JSON** — 히어스트링은 닫는 `"@` 가 열 0 이어야 하고 YAML 은 들여쓰기에 민감하다. 붙여넣기 안전성이 주제인 개정에서 이 의존을 없앴다. 생성 JSON 의 `spec.data` 가 배열이고 `template.metadata` 가 `{}` 인 것을 확인했다.
3. **`-notcontains` 제거** — 노드 이름·정책 이름 비교가 문화권 비교였다(안전 규칙 8 위반). `[string]::Equals(…, Ordinal)` 로 바꿨다.
4. **`curl`/`vault` 응답 빈 값 처리** — `curl.exe … | ConvertFrom-Json` 은 빈 응답에서 바인딩 오류를 내 원인을 알 수 없는 메시지가 뜬다. 먼저 raw 를 받고 빈 값을 명시적으로 판정한다.
5. **`vault kv list` 를 참고용으로 강등** — 판정에 쓰지 않고 실패 시 경고만.
6. **요약 말미 문구** — "이 실행이 kv 에 새로 쓴 경로: N 건"을 `$seedLog` 에서 계산해 출력.

## 2. 통째 붙여넣기 안전성 설계

네 블록 모두 **파일 전체가 최상위 문장 1개**(`& { … }`)다. 하네스가 매 실행 `EndBlock.Statements.Count == 1` 을 출력한다.

- 한 문이라 PSReadLine 은 중괄호가 닫힐 때까지 입력을 모으고, **전체가 파싱된 뒤 한 번에 실행**된다. 중간 줄이 단독 실행되는 경로가 없다.
- 블록 안 **빈 줄 0** — PSReadLine 이 없는 기본 콘솔 호스트가 빈 줄에서 입력 수집을 끝내는 동작에 대한 방어.
- 파일 끝은 `}` + 개행 1개(`0A 7D 0A`). 마지막 `}` 뒤에 남는 문자가 없으므로 첫 `Read-Host` 가 잔여 텍스트를 먹지 않는다(원본 block2 의 끝은 `0A 20 20`).
- 모든 정지점은 `$Host.UI.RawUI.FlushInputBuffer()` 로 콘솔 입력 버퍼를 비운 뒤 **단어**를 요구한다 → 미리 눌린 Enter(type-ahead)나 붙여넣기 잔여 줄로는 통과하지 않는다.
- `$ErrorActionPreference = 'Stop'` 이 `& { }` 안에 있어 세션 설정을 오염시키지 않는다(실측: 바깥은 그대로).

## 3. 하네스

`harness.ps1` 은 PowerShell **함수가 native 명령보다 우선**하는 성질을 이용해 `vault`·`kubectl`·`curl.exe` 를 가리고, `Read-Host`·`Set-Clipboard`·`Start-Sleep`·`Get-Date`·`Get-ItemProperty`·`Test-Path` 를 모의한다. 모의 vault 는 메모리 kv v2(버전·CAS·soft-delete/destroy·metadata·rollback·list·`-field`)를 흉내 내고 stdin JSON 을 받으며 `$global:LASTEXITCODE` 를 설정한다. 모의 kubectl 은 Secret/ExternalSecret 상태와 Orphan 인수·주기 refresh(300초)를 흉내 낸다. 시간은 가상이다(`Start-Sleep` 이 가상 시계를 진행).

가짜 값은 특수문자(`<>&'"\`)·base64·끝 개행 없음을 포함하고, 유니코드 값은 음성 시나리오 전용이다. **모든 시나리오가 "가짜 시크릿 문자열이 어떤 스트림에도 한 번도 나오지 않았는가"와 "`VAULT_TOKEN`·`VAULT_ADDR` 가 남지 않았는가"를 공통으로 검사한다.**

## 4. 하네스가 증명하지 못하는 것

모의는 **내가 가정한 출력 형식**을 되돌려줄 뿐이다. 아래는 첫 라이브 실행에서 확인해야 한다.

1. **`vault` CLI 의 실제 출력 형식** — `kv get -format=json` 의 `data.data` 구조, `kv metadata get -format=json` 의 `versions.<n>.{deletion_time,destroyed}` 키 이름, `token lookup` 의 `data.policies`. 하나라도 다르면 `$state`/`$readField` 가 fail-closed 로 멈춘다(오판이 아니라 중단이다).
2. **없는 경로에 대한 `vault kv metadata delete` 의 종료 코드** — v2 는 이 가정을 **쓰지 않는다**(사전 정리는 `$state` 로 존재를 확인한 뒤에만 delete). 프로브의 `finally` 만 무조건 delete 를 부르는데, 가정이 틀리면 **경고 1줄**이 뜰 뿐 중단되지 않는다.
3. **`vault kv rollback "-version=N"` 의 2.0.4 동작** — 실패하면 exit 비0 → 명확한 문구로 throw 한다. 성공 시 새 버전 번호가 `cur+2` 인지도 미확인이라 v2 는 그 숫자를 문면에 쓰지 않는다.
4. **`kubectl` jsonpath 표기** — `{.data['api-token']}`(대괄호·따옴표)과 `{.metadata.labels['reconcile\.external-secrets\.io/managed']}` 의 이스케이프. 모의는 정규식으로 해석하므로 실물 kubectl 의 파서와 같다는 보장이 없다. 다르면 빈 문자열 → fail-closed.
5. **ESO 2.10.0 의 실제 동작** — Orphan 인수가 `managed` 라벨을 다는지, ES 에 없는 키를 지우는지, Retain + Periodic 에서 재생성이 정말 주기 refresh 에만 일어나는지. DR1 이 이것을 **재기 위한** 드릴이므로 모의값(300초·라벨 true)은 기대치일 뿐이다. `managed` 라벨 하드 판정은 ESO 가 라벨을 안 다는 구현이면 **정상 상황에서도 중단**시킨다 — 그때는 드릴 결과로 판정 문면을 고치고 다시 돌린다(라이브 영향은 드릴 객체뿐).
6. **터널 토큰의 실제 형식** — `base64(JSON{a,t,s})` 는 미확인이다. OP1 B) 의 참고 줄(`tunnel=True · dns-token=False`)로 확정한 뒤에야 정정 블록의 형식 게이트를 신뢰한다.
7. **콘솔 고유 동작** — Ctrl+C 중 `finally` 절단(PS-03), 기본 콘솔 호스트의 빈 줄 종료(PS-12), 입력 버퍼 type-ahead 소비 비율(PS-05). 모의에서는 재현 불가라 **방어만** 했다.
8. **`kubectl delete --wait` 의 finalizer 대기** — 모의 delete 는 즉시 끝난다. `"--timeout=90s"` 가 실제로 걸리는지는 라이브에서만 확인된다.
9. **클립보드·레지스트리·전사 정책** — 모의라 실제 `Set-Clipboard` 는 호출되지 않는다(호출 횟수만 센다).
10. **모의 인자 전달의 한 가지 차이(수정함)** — `get externalsecret,secret` 은 파서가 `ArrayLiteralAst` 로 만든다. **native 명령에는 콤마로 이어 붙인 한 인자로 전달**되지만(probe4 실측 — 즉 실물 kubectl 은 정상) PowerShell **함수**는 `Object[]` 를 받아 문자열화하면 공백으로 이어진다. 하네스는 이 차이를 보정한다(`Norm-Args`). 이 항목은 원본·v2 블록의 결함이 아니라 하네스의 충실도 문제였다.

## 5. 남은 위험(라이브 실행 시)

- **oci/s3 값 검증의 부재** — 이 경로만 대조할 원본이 없다. v2 는 토큰 오입력·동일 클립보드 2회·비ASCII를 잡지만 "OCI 키가 맞는가"는 증명하지 못한다(키 모양 검사는 미확정이라 넣지 않았다).
- **`kubectl` 자식 프로세스의 `VAULT_TOKEN` 상속** — B) 단계의 `kubectl` 호출은 `VAULT_TOKEN` 이 env 에 있는 상태에서 돈다. 사전 점검을 토큰 입력 전으로 옮겨 노출 구간을 줄였을 뿐, B) 자체의 상속은 남는다(설계상 같은 창 원칙).
- **`managed` 라벨 하드 판정**(위 4-5)과 **형식 게이트**(4-6)가 첫 실행에서 정상 동작을 막을 수 있다. 둘 다 중단 방향이고, 드릴 대상은 비밀이 아니다.
- **정정 블록의 `$fixPath` 는 여전히 사람이 고르는 상수다.** 표에 없는 경로면 즉시 중단하지만, 표 안의 "다른 쪽"을 고르는 오선택은 형제 값 해시 대조와 형식 게이트로만 걸러진다.

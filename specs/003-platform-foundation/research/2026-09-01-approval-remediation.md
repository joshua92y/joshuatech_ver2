# Approval 리뷰 시정 결정표 (2026-09-01)

입력: `reviews/2026-09-01-approval.md` 종합 의견 1–25. 사용자 결정: "수정 후 재검토". 이 표가 spec/plan/tasks/contracts 편집의 단일 기준이다 — 편집자는 여기 적힌 값·이름만 쓰고, 표에 없는 결정은 만들지 않는다.

공통 규약(모든 파일 공통):
- 네임스페이스 확정: `kube-system`(traefik·coredns·metrics-server) · `argocd` · `vault` · `external-secrets` · `cert-manager` · `cnpg-system` · `data`(pg-main·kafka·dragonfly) · `identity`(authentik·openfga) · `jt-dev` · `jt-prod` · `monitoring`(alloy) · `system-upgrade` · `cloudflared` · `reloader`. `observability`라는 이름은 쓰지 않는다(→ `monitoring`).
- 버킷 3개: `jt-tfstate`(OpenTofu state, IAM 사용자 `svc-tfstate`만) · `jt-backup`(CNPG barman, IAM 사용자 `svc-s3-backup`만, versioning) · `jt-backup-platform`(K3s SQLite 번들 + Vault Raft 스냅샷, 노드 A 인스턴스 프린시펄이 `OBJECT_CREATE`·`OBJECT_INSPECT`만, versioning, lifecycle 30일). 세 버킷 전부 `NoPublicAccess`.
- 동적 그룹 `jt-node-a`(노드 A OCID만): KMS `use keys` + `jt-backup-platform` 쓰기. 노드 B는 동적 그룹에 없다.
- 헬스 엔드포인트 3개: `/healthz`(liveness, 프로세스만) · `/ready`(readiness, **DB만**) · `/health`(상세: db·dragonfly·kafka_producer 상태 JSON, 항상 200). 기존 문서의 `/health` = 상세, `/healthz` = liveness로 통일.
- 타임아웃·재시도 표(계약·settings 공통): BFF→pod fetch 3 s(AbortController) · pod→Authentik 5 s × 3회 지수 백오프(최대 5분, Celery) · Kafka `delivery.timeout.ms` 30000 · Dragonfly `socket_timeout` 0.2 s · PG app role `statement_timeout 15s`·`idle_in_transaction_session_timeout 30s` · ESO `refreshInterval 5m` · `/session/check` BFF 캐시 2 s.
- Dragonfly 조회 실패 = 비헬스 경로 503(RFC 9457 `type: …/denylist-unavailable`), fail-closed.
- 테넌트 식별자는 어디서나 UUID: Authentik 그룹 `tenant:<uuid>`, claim `tenant_id`(uuid), FGA object `tenant:<uuid>`, Kafka 파티션 키 `tenantid`(uuid). slug는 `Tenant.slug` 컬럼에만.
- E2E 신원: Authentik 로컬 사용자 `e2e@joshuatech.dev`(비밀번호·TOTP 시드는 Vault `kv/{env}/e2e`), GitHub 테스트 계정은 **만들지 않음** — 소셜 로그인(US4 AC1)은 운영자가 브라우저로 1회 수동 검증하고 그 스크린샷을 tester 보고에 첨부. 운영자 개인 계정 자격은 어떤 환경변수·파일에도 넣지 않는다.
- 에이전트·tester·CI 클러스터 자격: SA `agent-view`(ns `kube-system`) = ClusterRole `view` 집계 + `applications.argoproj.io` get/list + Role(`vault` ns) `pods/portforward`. `kubectl create token agent-view -n kube-system --duration=8h`로 만든 kubeconfig만 배포. admin kubeconfig(`k3s.yaml`)는 운영자 비밀번호 관리자에만. Vault seal 상태는 `kubectl port-forward svc/vault 8200` + `GET /v1/sys/seal-status`.

## 반영 규칙
- spec.md·plan.md·tasks.md·contracts·data-model.md·quickstart.md만 편집한다. research.md·checklists·reviews는 손대지 않는다.
- tasks.md: 새 task는 해당 phase 안 실행 순서 위치에 삽입하고 전체를 재번호(`T001…`)한다. 본문·Dependencies·Notes의 `Tnnn` 참조도 같은 매핑으로 갱신한다. 새 task는 tests-first 구조를 지킨다(테스트 task가 구현 task보다 앞).
- 문구는 한국어, 식별자는 영어. 값은 이 표의 값만.

# Contract: Django pod 템플릿 (`templates/django-pod`, copier)

`copier copy --trust --defaults --data pod_name=<pod> templates/django-pod apps/<pod>`로 생성되는 pod의 계약(`--trust`는 `copier.yml`의 `_tasks: uv lock` 때문에 필수 — 2026-11-02 T065). 생성물은 수정 없이 테스트를 통과하고, `packages/django-common`에 의존한다. 거부 목록 키·ACL은 contracts/denylist.md, 네트워크 허용은 contracts/network-policy.md, Vault 경로는 data-model §8.

**렌더 · 검사 전용 생성(T072 보정 2026-11-07)**: `copier copy --defaults --skip-tasks --data pod_name=<pod> …`는 `_tasks: uv lock`을 돌리지 않아 `--trust`가 필요 없다 — CI kubeconform job과 템플릿 하네스의 변형 렌더가 쓴다. 이 생성은 형제 `packages/django-common`이 없는 배치(예: `$RUNNER_TEMP/gen/<변형>/apps/<pod>`)를 허용한다. 그 트리에서는 `uv lock` · `uv sync`를 하지 않고, 하네스 변형의 Python 실행은 기본 pod의 venv(의존 상위 집합)로만 한다 — 아래 생성 위치 규칙의 유일한 예외다.

**생성 위치·버전 규칙(2026-11-02 T065 보정)**: pod 디렉터리는 저장소 루트 기준 `apps/<pod>`에 있고 `packages/django-common`은 두 단계 위의 형제다 — 템플릿은 이 상대 배치(`../../packages/django-common`) 하나만 가정하므로 다른 깊이(예: `tests/fixtures/generated/<pod>`)에 바로 생성하면 의존성이 풀리지 않는다(렌더 · 검사 전용 생성은 위 예외 — T072 · 검사 하네스는 임시 미니 저장소 `<tmp>/apps/sample-pod` + `<tmp>/packages/django-common` 복사본으로 같은 배치를 재현한다 — 아래 §기본 테스트 6). 모노레포 안의 템플릿 경로는 git 저장소 루트가 아니므로 copier는 clone·태그 선택 없이 **작업 트리를 그대로** 읽고 `.copier-answers.yml`에 `_commit`을 남기지 않는다 → `copier update`는 SP-1에서 지원하지 않는다(재생성 뒤 diff로 갱신; 템플릿을 태그가 있는 독립 저장소로 내는 것은 후속 기능 — research DJANGO-D18의 "저장소 `pod-template`" 가정과의 편차, report.md 후보).

## 테이블 등급 (헌법 III · FR-034)

| 등급 | 모델 | RLS | 접근 |
|---|---|---|---|

# Rules for `e2e/` and the root `playwright.config.ts`

Design of record: `specs/003-platform-foundation/design/t077-design.md` (D3, D5, D10 and correction note 7 — the credential-free foundation and its exposure controls) and `specs/003-platform-foundation/design/t086-design.md` (D10, D11 — the T087 `site` project). Operating notes: `e2e/README.md`. The behavior under test is governed by `contracts/bff-api.md` and `.claude/rules/web.md`; on conflict the contracts prevail — amend them first.

## Layout and runs

- `e2e/` is the source tree of the root Playwright install, not a workspace package: `@playwright/test` (exact pin, 1.65.1) is the root's only devDependency, the root `package.json` has no scripts, and the root `playwright.config.ts` (`testDir: './e2e'`) is the only Playwright configuration. The `config-hygiene` selftest pins the resolved config's named fields, and the `tracked-files` selftest pins the exact file set under `e2e/` (`git ls-files --cached --others --exclude-standard -- e2e`) — a new file enters only together with the change to that list (T077).
- Run Playwright only through the launcher, `node e2e/lib/launch.mjs <mode>` with exactly one argument: `selftest` (no browser, no network — the run-all `e2e-selftest` slot), `selftest-browser` (local `page.setContent` pages and 127.0.0.1 stand-in servers only), `needle` (the exposure needle test), `list` (per-project test counts), `live-red` (credential-free GETs to the public hosts — the controller's red observation; builders and the tester never start it on their own), `site` (the T087 `site` project against `BASE_URL`, with `JT_E2E_SITE_MODE` `local` or `prod`) and `site-red` (a closed loopback port — the red signature is `[gate] site-absent until T091`). An argument-less `pnpm exec playwright test` runs the two selftest projects only.
- The launcher creates a run-owned root `%TEMP%\jt-e2e\<runId>\` (outputDir, evidence, logs, the child's `TEMP`/`TMP`) and removes it afterwards; the child env is an allowlist (`SystemRoot`, `PATH`, `USERPROFILE`, `LOCALAPPDATA`, `TEMP`, `TMP`, the run variables and the mode's own values), and the launcher prints env names, verdict lines and counts only. It is Windows-only until T093 adds the Linux CI job.
- Projects load only under their flag: `selftest` and `selftest-browser` always; `needle`/`needle-control` with `JT_E2E_NEEDLE=1`; `live` with `JT_E2E_LIVE=1`; `site` with `JT_E2E_SITE=1`. `needle` together with `live` stops at config load (`[guard] needle-live-conflict`), and `site` is exclusive with both (`[guard] site-conflict`). No `webServer`, no top-level `use.baseURL`, no `executablePath` or `channel`.
- A credentialed (live) run happens only inside a reviewed credential block: `JT_E2E_BLOCK` must equal the root config's `metadata.jtApprovedBlock` (today `null`, so live always stops at `[guard] outside-reviewed-block (T077-a)`), and the tester's Credentials rules (`.claude/agents/tester.md`) apply.

## Artifacts: zero

- Every project runs with `trace`, `video` and `screenshot` off; the reporter is `list` alone (no HTML, blob, json or junit — HTML step titles carry `fill` values in clear); `preserveOutput: 'never'` (the needle run alone uses `'always'` so its scan sees failure artifacts); `PLAYWRIGHT_NO_COPY_PROMPT=1`, `captureGitInfo` off, `updateSnapshots: 'none'` and `snapshotDir` under the outputDir; the outputDir and the evidence directory lie outside the repository. `workers: 1`, `fullyParallel: false`, `retries: 0`, `forbidOnly: true`.
- globalSetup re-asserts this at run time. It counts `e2e/.auth/` residue before any other guard (residue → deleted, then `[state] previous-run residue count=<n>` — a suspected exposure); it stops on debug, proxy and TLS env (`PLAYWRIGHT_*`, `PW_*` and `PWTEST_*` too, except `PLAYWRIGHT_TEST=1` and `PLAYWRIGHT_NO_COPY_PROMPT=1`; `NODE_OPTIONS` is an allowlist) and on CLI overrides (`--trace`, `--reporter`, `--output`, `--workers`, `--retries`, `--update-snapshots` and the like); and it re-checks the resolved FullConfig. Per-file option overrides are caught by the auto fixture of `e2e/lib/test-base.ts` (`[guard] fixture-override <name>`), so specs, needle and selftest-browser import `test` only from `e2e/lib/test-base.ts` — never from `@playwright/test` directly.
- `test-results/`, `playwright-report/` and `blob-report/` are gitignored at any depth; stage files by name only (never `git add -A`). The CI site job (T093) uploads no test-results, report or trace artifact.
- Evidence screenshots come only from `e2e/lib/evidence.ts`, and only when every mask locator's count equals the expected row count (else `[product] mask-target-missing`); the files stay in `JT_E2E_EVIDENCE_DIR`, never get committed, and reports carry file names, SHA-256 and the masked fields only.

## Credentials and exposure

- Credential env (`JT_E2E_SECRET_*`) and the needle set (`JT_E2E_NEEDLE_SET`) are read only by `e2e/lib/env-contract.ts`, inside a test body after its reach step passed, once — then deleted from `process.env`. A missing value is an `[env]` FAIL that lists names only, never a SKIP. The mode is decided by the project name, never by env.
- Every request and navigation (`request.*`, `page.request`, `context.request`, `goto`, `waitForURL`, `waitForResponse`) goes through `e2e/lib/http.ts`, which rethrows a new error carrying only `<METHOD> <origin+pathname> failed (<code|status>)` and no `cause`; compare `response.status()` numerically (never `toBeOK()`). Secret fields are filled only through `e2e/lib/secret-input.ts`. Assertions use origin + pathname for URLs, counts for IP and UA cells, and only the presence of `type`/`request_id` for problem bodies.
- The static-gate selftest (`e2e/selftest/static-gate.test.ts`) enforces these rules on `e2e/**` and the root config: its rule list is the inventory, every rule has a planted positive control, and the planted keys equal the rule ids. In outline: recording, HAR, attachments, `page.pause`, request/response/console listeners, value-bearing matchers and extractions (`toHaveURL(`, `toHaveValue(`, `inputValue(`, `textContent(` …) and the pull APIs that expose headers, bodies or logs — `allHeaders(`, `headerValue(`, `headerValues(`, `headersArray(`, `postData`, `.response(`, `requests(`, `consoleMessages(`, `pageErrors(`, `existingResponse(` — are banned everywhere (`headers()` stays allowed); `console.`, `process.stdout` and `process.stderr` belong to `e2e/lib/out.ts` plus the named exceptions (`launch.mjs`, `scan-needle.mjs`, the needle-control spec); `storageState({ path` belongs to `e2e/lib/auth-dir.ts` and `screenshot(` to `e2e/lib/evidence.ts`.
- T087 exceptions and scope rules: `e2e/lib/site-probe.ts` is the only file allowed a `request` listener (rule `listener-request`) and is on the `evaluate` allowlist; it returns numbers and booleans only, never names its listener parameter `request`, reads no `url()`, and prints only through `out.ts` (the `emit-args` rule applies). Only `e2e/hello.spec.ts` and `e2e/selftest-browser/site-probe.test.ts` may import it (`site-probe-import`). In `e2e/*.spec.ts`, the argument code of `expect(` must not touch `headers`, `.body` or `cookies(` (`expect-args`).
- Output lines go through `e2e/lib/out.ts`: the machine-readable part (before the first ` — `; before ` -- ` in launcher and harness lines) is ASCII and carries no values. Failure prefixes: `[gate]` (implementation absent — the only red evidence), `[product]`, `[env]`, `[decision]`, `[guard]`, `[state]`.
- Needle values are generated by the launcher per run and are never a literal in source, fixtures or selftest expectations; `needle=PASS` needs the exact intended failures, zero hits on every surface and every per-path positive control caught. Rerun `selftest`, `selftest-browser` and `needle` whenever `@playwright/test` changes.
- The login-lock marker (`<token home>\AppData\Local\jt-e2e-lock\e2e-login-lock.json`) stops every live run until an operator has checked the cause; nothing in `e2e/` deletes it.

## The `site` project (T087)

- `validateSiteTarget(BASE_URL, JT_E2E_SITE_MODE)` (`e2e/lib/site.ts`) allows exactly: `local` = the origin `http://127.0.0.1:<port>` or `http://localhost:<port>`; `prod` = exactly `https://joshuatech.dev`. Anything else → `[guard] site-target-not-allowed`, without the value. `preview.joshuatech.dev` sits behind Access and is never an automated target; neither is `next dev`.
- `prod` mode requests the public apex: run it only when the controller's task slice names it. Keep `pace()` ≥ 200 ms between calls in every mode (the Free Rate Limiting rule).
- Specs read no env: the site mode reaches `e2e/hello.spec.ts` through project `metadata` and the `baseURL` fixture. Every test first passes `reach` (`freshGet(<base>/ko)`) before any absence assertion — the only exception is the local `/api/health` skip. Step lines are `T087 <step> PASS|FAIL <reason>` with no values.
- Reach classification: local connection refused without the web scaffold → `[gate] site-absent until T091` (the red signature); with the scaffold → `[env] site-server-not-running`; another network error → `[env] network (<code>)`; a 200 `text/html` carrying `data-jt-app="web"` → PASS; any other local response → `[product]`; prod 52x/5xx → `[env] origin status=<n>`; another prod response → `[env] prod-site-not-v2` until T094, `[product]` after.
- Contract cookie names (`__Host-jt_session`, `__Host-jt_csrf`) are the tests' own constants (`e2e/lib/bff.ts`), never imported from the gateway. Placeholder `jt_session=` strings in the needle and selftest fixtures assert no contract name and stay as they are.

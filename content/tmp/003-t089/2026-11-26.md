# 003-platform-foundation T089 — BFF gateway 시험 먼저: 일곱 라우트 계약 · 기기 단위 로그아웃 · 캐시가 가린 누출 단언 (2026-11-26)
> 11-23 ~ 11-26을 함께 담는다. 설계 11-23 ~ 24 · 빌드 11-24. 그날 세션은 수정 라운드 도중 주간 사용 한도로 끊겨 기록을 남기지 못했다. 11-26에 재개해 수정 두 라운드 · 검증을 마치고 빨강을 다시 관찰했다. tick은 이 기록과 같은 커밋이다. 파드 조각 ⑤ UD-7a(ㄴ)(tasks.md 밖 · tick 없음 · 커밋 따로)는 「배운 개념」의 ⑤ 절에 담는다.

## 문제
- 웹 앱의 BFF(Route Handler 7개 — login · callback · logout · refresh · session · health · proxy)를 구현(T092)하기 전에 계약을 fetch mock 시험으로 고정해야 했다. 상류(Authentik · identity-admin)에는 시험이 주입한 `fetch` 하나로만 닿는다.
- 계약은 과제 문면(PKCE · JWE 쿠키 · 교환 캐시 5분 · `/session/check` 2 s 캐시 · 하류 헤더 정적 맵 · 3 s 시간 초과 · 프록시 정적 맵 · return_to · 이미지 로더 폴백 · 로그 위생)보다 넓었고, 로그아웃 범위 같은 사용자 결정이 열려 있었다.
- 비밀이 흐르는 경로다. 세션 · CSRF · PKCE 쿠키, refresh · 교환 토큰, Access 서비스 토큰 값이 하류 · 로그 · 응답 어디에도 새지 않음을 「값을 찍지 않고」 증명해야 했다.

## 배운 개념
- **로그아웃의 관례 범위는 「그 기기」다(UD-7 동향 조사).**
  - BFF 표준(RFC 10017)은 범위를 앱에 맡긴다. ASVS 5.0 · NIST 800-63B-4 · OWASP 치트시트는 로그아웃을 그 세션으로 본다. 기본값이 「전체」인 업계 사례는 하나뿐이었다.
  - 본문 생략 = 이 기기, 「모든 기기」는 명시 `{"all_devices": true}`만이다. 이 기기 요청은 어떤 실패에서도 「모든 기기」로 넓혀 보내지 않는다.
  - 본문은 네 꼴만 받고 그 밖은 400이다. 모호한 본문을 어느 쪽으로 접어도 결함이 조용히 좁아지거나 넓어진다.
- **앱 로그아웃만으로는 IdP 세션이 남는다(UD-7a(ㄱ)).**
  - Authentik 기본 앱 로그아웃 흐름은 앱 세션만 끝낸다. 공용 PC의 다음 사람이 비밀번호 없이 앞 사람으로 로그인된다.
  - 그래서 로그아웃 응답에 BFF가 만든 end-session 주소를 `x-end-session-url` 헤더로 싣고, 클라이언트가 그 주소로 이동한다.
  - 값의 원천은 설정과 요청 URL origin뿐이다. 시험은 요청 질의 · `origin` · `referer` · `x-forwarded-host` · `host` · `forwarded`에 적대 값을 넣어도 헤더 값이 그대로인지 본다.
  - `id_token_hint`는 싣지 않는다(쿠키가 커지고 URL로 기록 · 로그에 남는다). 그 대가로 OP가 확인 화면을 띄울 수 있다(OIDC RP-Initiated Logout 규격) → 「추가 클릭 0」은 T081에서 잰다.
- **`__Host-` 쿠키 접두(B-6 · N-9).**
  - 브라우저는 이 접두의 쿠키를 Secure · `Path=/` · Domain 없음일 때만 받는다. 형제 서브도메인(PR 코드가 도는 preview 포함)이 같은 이름을 심어 세션을 고정하는 길이 막힌다.
  - `__Secure-`는 Domain을 막지 않아 PKCE 쿠키도 `__Host-jt_pkce; Path=/`로 했다. 대가로 300 s 동안 같은 origin 요청마다 실리므로, 콜백 밖 라우트에서도 그 값을 바늘로 본다.
  - 접두 없는 옛 이름은 읽지 않는다(네 라우트 각각 시험).
- **열린 리디렉션은 접두 검사로 못 막는다.**
  - `/\evil…` · 탭이 든 경로 · `/..//evil…`은 WHATWG 해석 뒤 다른 origin이나 `//`로 시작하는 pathname이 된다.
  - → 해석 결과의 origin · pathname으로 판정하고, 디코딩 값은 출력 가능 ASCII만 받는다. 접두만 보는 변이 · 해석 미검사 변이 · ASCII 검사 생략 변이가 각각 잡힌다.
- **캐시가 누출 단언을 공허하게 만들었다 — 이번 과제의 핵심 교훈.**
  - G8-2는 한 인스턴스로 proxy → session → health → logout을 차례로 부르고 「들어온 쿠키 값이 하류에 0」을 봤다.
  - 그런데 2 s 확인 캐시와 교환 캐시를 공유해, session 다리는 하류 호출이 0이었고 logout 다리의 확인 · refresh · 교환도 캐시에 적중했다. 「하류에 바늘 0」은 하류가 없어서 참이었다.
  - 검증이 그 라우트들에서만 값을 흘리는 변이 넷을 만들었고, 넷 다 326/326 초록으로 살아남았다.
  - 고친 꼴(G8-3): 라우트마다 새 인스턴스 + 하류 호출 종류 · 순서를 정확히 단언한다(session `[check]` · refresh `[check, token-refresh]` · logout 다섯 종류). 새는 자리가 될 호출이 실제로 나가야 통과한다.
  - 일반화: 「X가 0」 단언은 「X가 생길 경로가 실제로 돌았다」는 양성 단언과 짝이어야 한다(바늘 0은 로그 줄 ≥ 1 먼저 · 상류 0은 응답 상태와 함께).
- **경계는 사례가 있어야 지켜진다.**
  - PKCE 쿠키는 `created_at + 300 s`를 「넘으면」 만료다 → 정확히 300 s는 유효. 사례가 없을 때는 `>=` 구현이 통과했다.
  - 종료 헤더는 issuer · client_id 「둘 다」 유효할 때만 붙는다 → client_id만 빈 문자열인 인스턴스를 더했다. 키를 지우는 꼴이면 이름 존재만 보는 구현이 통과한다.
- **기대값은 구현에서 가져오지 않는다.**
  - 쿠키 이름은 시험 자기 상수로, JWE는 Web Crypto 오라클로 따로 본다. 가짜 비밀은 전부 실행 중에 조립하고(자격 든 URL까지 — 이전 오탐 선례), 리터럴은 오라클 자체 검증용 공개 RFC 벡터뿐이다.
  - 없는 모듈의 동적 import는 사례마다 따로 실패한다(실측). gateway를 사례 첫 줄에서 늦게 적재해 빨강을 사례 단위로 보고, gateway를 적재하지 않는 도우미 자기 시험은 처음부터 초록으로 둔다.

### ⑤ UD-7a(ㄴ) 파드 조각 — `revoked:sid` 값 = 폐기 시각 · 세션 단위 하한
- **결함(W35)**
  - 거부 목록 키 `revoked:sid:{sid}`의 값이 `1`(있으면 폐기)이었다.
  - 같은 브라우저에서 로그아웃 직후 다시 로그인하면 Authentik 세션이 같아 sid도 같다 → 키가 사는 동안(최대 330 s) 새 세션까지 거부됐다. 「이 기기」 로그아웃을 기본으로 고르면 바로 드러나는 결함이었다.
- **고친 것**
  - 값 = 폐기 시각(nbf — 사용자 단위 `revoked:sub`와 같은 꼴).
  - pod 미들웨어(django-common)는 「값 > 토큰 iat」(같으면 통과), identity-admin `/session/check`는 `issued_at < nbf`인 세션만 inactive로 본다. BFF가 보는 의미는 그대로라 T089 시험 영향은 0이다.
- **세션 단위 하한(T-c · 컨트롤러 결정)**
  - `revoked:sid`는 330 s 그대로 두고, `/session/check`만 읽는 `identity-admin:sid-floor:{sid}`(30 d)를 더했다.
  - 값만 바꾸면 RFC 7009 폐기가 실패했을 때 330 s 뒤 복사 쿠키가 되살아난다(E13). `revoked:sid`를 30일로 늘리면 pod가 읽는 키 수명이 spec과 어긋난다.
  - 사용자 단위와 같은 구조(330 s 키 + 30 d 하한)이고, 새 키가 identity-admin 자기 접두 안이라 ACL · gitops 변경은 0이다.
- **값은 정규 꼴로만 읽는다(N-16)**
  - 네 값(`revoked:sub` · `revoked:sid` · 하한 둘) 모두 ASCII 숫자 1–19자만 받고, 밖이면 503이다.
  - 존재 판정은 어떤 값이든 닫혀 있었지만, `int()` 비교는 손상 값(`-5` · 앞 공백 · `1_000`)을 조용히 「폐기 아님」(열린 쪽)으로 읽는다.
- **시계 둘**: `issued_at`은 Authentik 시계, nbf는 identity-admin 시계다. Authentik이 앞서면 로그아웃 직후 시작한 같은 sid 세션이 비켜 갈 수 있고, 미래 iat 규칙 때문에 그 폭의 상한은 60 s다(T081에서 잰다).
- **시험이 놓친 결합(리뷰 D-2)**
  - 30 d는 보존 기간 상수 하나에 묶었지만, 상수를 덮어써 창이 함께 움직이는지 보는 시험에 sid 행이 없었다.
  - 30일을 리터럴로 쓴 변이 넷(창+TTL · 창만 · TTL만 · `apply_sid`)이 모두 살아남았다 → sid 행 셋을 더하자 넷이 각자 다른 단언에서 잡혔다. 같은 종류의 공백이 기존 사용자 단위 경로에 하나 남았다(범위 밖 · 기록).
- **빨강 예측이 틀린 곳(D-5)**: 값 꼴만 바뀐 두 시험은 옛 코드에서도 초록이었고, 세 시험은 표와 다른 원인(존재 판정 · 키워드 `TypeError`)으로 빨강이었다. 예측이 틀린 것이지 구현 결함은 아니지만, 합격선이 「원인이 표와 같다」였으므로 정정 노트로 남긴다.
- **결과**
  - 시험 먼저 빨강(바뀐 노드 — django-common `19 failed, 7 passed` · identity-admin `20 failed, 2 passed`) → 구현 → django-common `779 passed` · identity-admin `526 passed`(검증 V2) · 템플릿 하네스 949. 변이 10종 모두 검출.
  - 렌더본은 `copier recopy` 뒤 jinja와 같은 줄만 바뀌었다. 라이브 변경 0 — identity-admin 재배포는 다음 main 발행이라 사용자 결정 뒤다.
- **환경**: 템플릿 하네스의 이미지 시험 6건이 처음엔 arm64 binfmt 미등록(`exec format error`)으로 오류였다(빌더 지시문에 등록 단계가 빠졌다). 바뀐 인증 코드를 담은 이미지를 띄우는 시험이라 무관하다고 단정할 수 없어, 컨트롤러가 등록한 뒤 6건을 다시 돌려 통과시켰다(합 949).

## 선택과 대안
- **UD-7(사용자 결정)**: 사용자가 「최신 트렌드」를 물어 표준 · 지침 · 업계를 조사했다. 조사 종합은 「SP-1 한시로 사용자 단위」를 권했다(지금 코드로 인수 기준 1 s를 지키는 길). 사용자는 「관례대로 기기 단위로 하고 결함 고쳐 관례 기준으로 기준 조금 내려도 좋아」로 기기 단위를 골랐다.
  - 기준 조정: 이 기기 경로는 복사 쿠키로 BFF를 거친 호출이 2 s 안에 401이다(확인 캐시 2 s). pod 즉시 거부는 없고(교환 토큰에 sid 없음) 교환 토큰 잔여는 ≤ 330 s다. 「모든 기기」는 기존 인수 기준 그대로다.
- **UD-7a = 둘 다(사용자 결정)**: (ㄱ)은 공용 PC 틈을, (ㄴ)은 재로그인 결함을 닫는다.
- **end-session 응답 꼴 L2**: 상태 · 본문은 그대로 두고 헤더만 더한다. 200 JSON · 폼 POST 303 · 202 + Location은 각각 tick된 T079 판정 코드 · CSRF 계약 · 응답 규칙의 예외를 만들어야 해서 기각했다.
- **UD-8(사용자 결정 「관례에 따른다」)**: callback은 identity-admin을 부르지 않는다. 폐기 뒤 재로그인은 IdP 쪽 세션 종료로 막는 것이 업계 관례다.
- **logout 내부 refresh `invalid_grant` = 503**(204 아님): 다른 isolate의 회전 경합이면 세션이 살아 있는데 성공으로 보인다. 재사용 감지 = 토큰 가족 폐기가 실측되면 204로 되돌린다.
- **남은 두 갈래(검증 V3-1)**: logout `all_devices: true` 갈래와 session inactive 갈래에는 적대 쿠키 사례가 없다(탐침 변이 둘 생존). 지금은 기록하고, T092 착수 때 시험 먼저 두 행을 더한다.

- **⑤ 배포**: 다음 main 발행(UD-1 재질문) — BFF가 처음 identity-admin을 부르기 전. 옛 값 `1`은 정규 꼴이라 503이 아니고 「폐기 아님」으로 읽힌 뒤 재적용(30 s)이 덮는다.

## 사고·오류
- **끊긴 수정 라운드의 반쪽 수정 둘(전체 경과는 T086 기록).** 재개한 T089 수정자가 첫 시도의 작업 트리를 실물로 대조하니 둘이 반쪽이었다.
  - 머리 주석은 설정 무효 인스턴스 (c)를 가리키는데 그 인스턴스가 없었다.
  - PKCE 바늘에서 login의 state를 빼는 예외가 있어, 들어온 state를 새 authorize에 다시 싣는 구현이 통과했다.
  - 교훈: 재개 지시문의 「첫 시도 흔적」은 근사다 — 반쪽인지는 변이로 판정한다.
- **기억으로 적은 RFC 벡터가 틀렸다.** 빌더가 RFC 7636 부록 B의 옥텟 배열을 기억으로 적었다가 verifier → challenge 쌍(SHA-256 일치)으로 바로잡았다. 교훈: 공개 시험 벡터도 계산으로 대조한다.
- **하위 에이전트의 규칙 위반(자진 신고 · 저장소 영향 0)**: ⑤ 수정자가 읽기 명령 몇 개를 `cd`로 시작했고, ⑤ 검증자는 스크래치 밖 임시 경로에 한 번 썼다가 지웠다.

# 003-platform-foundation T046 — 끝났다고 말하기 전에 한 번 더 돌린다: 시험 대상 제거와 마무리 검사 (2026-09-29)
> 3일차(시험 대상 제거 확인 → 마무리 검사 → 태스크 닫기). 실측 자체는 전날 끝났다.

## 문제
실측이 통과로 확정된 뒤에도 할 일이 남아 있었다. 시험을 위해 넣은 임시 워크로드를 Git과 클러스터 **양쪽에서** 치워야 하고, 반복 작업 동안 일부러 미뤄 둔 전체 검사를 한 번 돌려 "부분 검사만 통과한 상태"로 태스크를 닫지 않아야 한다. 전날 저녁에 시작한 전체 검사는 세션이 끝나면서 도중에 끊겼다.

## 배운 개념
- **prune을 끈 Application에서 "Git에서 지운다"와 "클러스터에서 지운다"는 별개의 두 단계다.** 이 Application은 Git에서 사라진 객체를 자동으로 지우지 않게 되어 있다(실수로 지운 선언이 운영 객체를 없애는 일을 막는 설정이다). 그래서 제거 변경을 머지하면 도구는 "동기화 안 됨 — 지워야 할 객체가 남아 있다"를 보이고, 사람이 그 객체를 지운 뒤에야 "동기화됨"으로 돌아온다. 머지 직후의 "동기화 안 됨"은 고장이 아니라 **예상한 중간 상태**다 — 절차에 미리 적어 두지 않으면 그 순간에 되돌리기를 고민하게 된다.
- **끊긴 검사의 "여기까지 통과"는 통과가 아니다.** 끊긴 전체 검사는 69개 중 59개까지 실패 없이 진행된 상태였다. 남은 10개가 같은 검사 묶음의 뒤쪽이라는 것만으로는 아무것도 말해 주지 않는다. 처음부터 다시 돌렸다.
- **부분 검사로 반복하고 전체 검사는 마지막에 한 번 — 이 방식의 대가는 "마지막 한 번"을 빼먹을 수 없다는 것이다.** 반복 중 시간을 아낀 만큼, 닫기 전의 전체 실행은 선택이 아니라 의무가 된다. 그래서 부분 실행은 CI 환경에서 아예 거부되게 해 두었다(부분 실행의 성공 종료를 전체 통과로 읽는 일을 막는다).
- **과제 문구의 확인 방법과 실제로 쓴 확인 방법이 다를 때는 둘 다 남긴다.** 과제는 "클러스터 범위 역할을 이름으로 세어 0"을 요구했고, 실측은 "배포 도구가 관리하는 객체 목록에 클러스터 범위 역할이 0"으로 했다. 뒤쪽이 더 엄밀하지만(이름이 달라도 잡는다) 읽기 전용 계정으로는 앞쪽을 직접 볼 수 없었다. 문구 그대로의 확인은 운영자에게 한 줄로 부탁했다.

## 선택과 대안
| 질문 | 택한 것 | 버린 것과 이유 |
|---|---|---|
| 끊긴 전체 검사 | 처음부터 다시 실행 | 남은 10개만 실행 — 부분 실행 필터로 가능하지만 "필터 없는 전체 실행 1회"라는 완료 조건을 만족하지 못한다 |
| 전체 검사를 돌릴 트리 | 머지된 주 브랜치 | 작업 브랜치 — 내용은 같지만(스쿼시 머지 · 트리 동일 확인) 기록에 남길 기준은 실제로 배포되는 쪽이다 |
| 클러스터 삭제 시각 | "머지 시각 이후"로만 기록 | 추정 시각 기입 — 출력에 시각이 없었다. 모르는 것은 모른다고 적는다 |

## 결과와 검증
- 시험 대상 제거 변경이 머지됐고, 운영자가 임시 워크로드와 시험용 Secret을 지웠다. 배포 도구의 상태는 머지 직후 "동기화 안 됨" → 삭제 뒤 "동기화됨 · 정상"으로 돌아왔다.
- 저장소 전체 검사(모노레포): 전부 통과.
- 렌더에서 과제의 요구 값을 다시 확인했다: 복제본 1 · 메모리 요청 50Mi · 플랫폼 노드 고정 · 보안 컨텍스트 네 항목 · 전용 서비스 계정.
- gitops 전체 자기검사(필터 없음): 69개 전부 통과. 실제 트리 정적 검사: 실패 0. 한 번 도는 데 약 1시간이 걸렸다.
- 클러스터 하네스: 이 태스크의 두 단언(배포 가용 · 클러스터 범위 권한 0과 인자 목록 정확 일치)이 배포 전의 기대 실패에서 통과로 바뀌었다. 남은 실패 넷은 아직 설치하지 않은 구성 요소와 만료된 조회 세션 때문이고 이 태스크와 무관하다.
- 시험 대상이 사라진 뒤의 상시 점검 명령을 실제로 실행해 기대 개수(관리 객체 12)와 맞는 것을 확인했다 — 문서에 옮긴 명령을 돌려 보지 않고 남기지 않는다.

## 사고·오류
- **백그라운드 검사가 세션과 함께 끊겼다.** 한 시간짜리 검사를 세션이 끝나 가는 시점에 시작했다. 끊긴 뒤 알림을 받고도 바로 원인을 확인하지 않았다 — 다음 작업을 시작하면서야 출력 파일을 열어 "실패가 아니라 중단"임을 확인했다. 비정상 종료 알림은 받은 즉시 출력부터 본다.

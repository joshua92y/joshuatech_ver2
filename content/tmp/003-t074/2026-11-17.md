# 003-platform-foundation T074 — 첫 main 발행과 dev 자동 bump 실측: 「사람 행동 0」을 반증으로 확인하기 (2026-11-17)
> push · PR 빌드 검사 · 통합 전제 · 통합 머지 · 첫 main 실행 · VD-5 판정 · 마감. 설계와 빌드는 앞 날짜 파일에 있다.

## 문제
어제 만든 발행 워크플로를 실제로 돌려 VD-5를 판정한다 — 봇의 dev bump PR이 사람 행동 없이 자동 머지되는가. 발행은 main에서만 열리므로, 재려면 기능 브랜치를 한 번 main에 통합(단계 통합)해야 한다. 통합 전에 갖출 것은 셋이다: App 설치 범위 축소, main의 필수 검사 추가, gitops의 첫 이미지 항목(seed) 머지. 판정은 「사람이 한 일이 없다」는 주장이라, 증거 수집과 반증을 따로 돌린다.

## 배운 개념
- **PR 빌드 검사의 값은 merge 커밋이다.** pull_request 이벤트의 `github.sha`는 PR head가 아니라 시험용 merge 커밋이다. 메타데이터 액션의 태그와 이미지 revision 라벨이 모두 그 값을 쓰고, 단언도 같은 값을 기대해 통과했다. main에서는 같은 자리에 진짜 main 커밋이 들어간다.
- **필수 검사에는 「출처」가 있다.** ruleset에 검사 이름만 더하면 출처가 「아무 출처」로 남는다 — 같은 이름의 commit status를 올릴 수 있는 어떤 토큰이든 그 검사를 채울 수 있다. 되읽기에서 integration id가 비어 있는 것을 보고 GitHub Actions로 고쳤다. 화면에서 바꾼 설정은 API 되읽기로 확인한다.
- **Environment의 `waiting`은 승인 대기만 뜻하지 않는다.** 브랜치 정책만 있는 Environment에서도 배포 상태가 1초 남짓 `waiting`을 거쳐 자동으로 진행했다. 승인 여부는 상태 이름이 아니라 승인 기록(approvals) · 대기 배포 · 보호 규칙의 검토자 목록으로 판정한다.
- **「누가 했나」의 표시는 귀속일 수 있다.** 실행 · 배포의 actor가 운영자 계정으로 보인 것은 통합 머지 push의 귀속이었고, 승인 기록은 0이었다. 봇의 PR · auto-merge · 머지는 GraphQL 타임라인과 REST 필드(작성자 · enabled_by · merged_by)가 모두 봇으로 일치했다.
- **「사람 행동 0」은 반증으로 확인한다.** 증거를 모으는 렌즈 하나와, 그 결론을 깨려는 렌즈 둘을 독립으로 돌렸다. 사람 행동 렌즈는 환경 승인 · 실행 승인 · 사람 커밋 · 리뷰 · 편집 · 수동 dispatch · 재실행 · 세션 중 설정 변경을 찾았다. 무결성 렌즈는 발행 digest가 끝까지 같은지 · 머지 커밋이 한 줄 교체인지 · 브랜치 삭제 · main 검사를 봤다. 셋 다 같은 판정(A)이었고, 반증 시도는 모두 실패했다.
- **attestation도 레지스트리의 「버전」이다.** 서명 증명을 레지스트리에 올리면 같은 패키지에 `sha256-<digest>` 태그의 매니페스트가 하나 더 생기고, 패키지 화면의 「Latest」가 그것을 가리킨다. 그래서 화면의 pull 예시는 이미지가 아니다 — 배포는 digest로 고정하므로 무해하다.

## 선택과 대안
- **통합 머지를 누가 실행하나**: 프로젝트 규칙은 머지를 결정하는 GitHub 동작을 운영자 전용으로 둔다(에이전트의 CLI가 운영자 계정이라 실행하면 성공하기 때문이다). 사용자가 「머지해」라고 했을 때 바로 실행하지 않고 규칙을 들어 확인했다 — 사용자는 「이번만 에이전트가 실행」을 골랐다. 예외 범위(이 머지 하나)와 이유를 기록했다. 뒤따를 수 있는 봇 PR의 실행 승인 · 사람 머지는 계속 운영자 몫으로 남겼다.
- **기록 커밋을 언제 올리나**: PR 빌드 검사 결과를 적은 문서 커밋을 바로 올리면 PR head가 바뀌어 CI를 다시 기다려야 한다. 로컬에 두고 통합 뒤 마감 커밋과 함께 올렸다(통합 머지는 확인한 head로 고정했다).
- **BuildKit 패치판**: 통합 시각이 발행 14일 원칙을 채우기 전이라 기존 판으로 통합했다. 갱신은 뒤 과제로 넘겼다.

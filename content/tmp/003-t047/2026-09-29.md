# 003-platform-foundation T047 — 검사를 CI에 연결하는 일은 "누가 그 검사를 끌 수 있는가"를 묻는 일이다 (2026-09-29)
> 1일차(조사 → 결정 다섯 → 계약 → 검사 6 보강 → 워크플로 배선 → 러너 실측). 렌더링 비교 코멘트 · 검사 확장 · 승격 워크플로는 다음.

## 문제
GitOps 저장소의 정적 검사는 지금까지 "PR 전에 로컬에서 돌린다"는 약속에 의존했다. 머지를 막는 필수 검사는 이름만 있었고 실제로는 비밀 검사 하나만 돌았다. 이 태스크는 검사 본체를 필수 검사에 연결한다.

연결 자체는 몇 줄이다. 어려운 것은 이 저장소에 **자동으로 PR을 열고 자동으로 머지하는 봇**이 있다는 점이었다. 봇의 PR은 사람의 승인 없이 머지된다. 그러면 질문이 바뀐다 — "검사가 도는가"가 아니라 "봇의 자격이 탈취됐을 때, 그 자격으로 검사를 끌 수 있는가".

## 배운 개념
- **PR의 검사는 PR 쪽의 코드로 돈다.** PR 이벤트로 도는 워크플로는 PR이 가져온 워크플로 파일과 스크립트를 쓴다. 검사 스크립트를 고친 PR은 고친 검사로 판정받는다. 사람의 PR이라면 리뷰가 막지만, 자동 머지되는 봇의 PR에는 리뷰가 없다.
- **플랫폼이 지켜 주는 범위는 생각보다 좁다.** 봇에게 워크플로 변경 권한을 주지 않으면 워크플로 파일은 못 바꾼다. 하지만 그 보호는 워크플로 디렉터리 하나뿐이다. 검사 스크립트, 설치 스크립트, 픽스처는 전부 보호 밖이다. 그래서 **봇을 제한하는 검사는 주 브랜치의 스크립트를 꺼내서 돌리고**, 도구 설치는 저장소의 스크립트를 부르지 않고 워크플로 파일 안에 적는다.
- **순서가 보안이다.** 같은 작업 안에서 PR 쪽 코드를 한 번이라도 실행하면, 그 뒤의 모든 검사는 오염된 환경에서 돈다(실행 경로 앞에 가짜 명령을 두는 식). 봇을 제한하는 검사는 PR 쪽 코드를 실행하기 **전에**, 실행 환경에 원래 있던 명령만으로 돌아야 한다. "어떤 검사를 넣을까"만큼 "몇 번째에 넣을까"가 중요했다.
- **"변경된 내용"을 계산하는 기준도 공격 면이다.** 두 커밋을 그냥 비교하면 PR 브랜치가 뒤처져 있을 때 주 브랜치 쪽 변경이 섞여 정상 PR이 실패한다. 공통 조상을 기준으로 바꾸니 새 문제가 나왔다 — 이력이 교차하면 공통 조상이 둘 이상이고, 도구는 그중 하나를 골라 준다. 공격자가 PR의 내용을 "골라질 쪽 + 허용된 한 줄"로 만들면 비교 결과는 깨끗한데 실제 머지 결과는 다른 파일을 바꾼다. 공통 조상이 정확히 하나가 아니면 실패하게 했고, 주 브랜치에 머지 커밋이 들어오지 못하게 저장소 규칙도 바꿨다.
- **줄 단위 검사는 "모양"이 아니라 "위치"까지 봐야 한다.** 허용된 형식의 줄만 바뀌었는지 보는 검사는, 그 줄을 **지우거나 다른 항목으로 옮기는** 변경을 통과시켰다. 형식은 맞지만 뜻이 바뀐다(한 항목의 고정값을 지우면 그 이미지는 고정이 풀린다). "삭제 한 줄 바로 뒤에 추가 한 줄"이라는 제자리 교체만 허용하고, 교체된 두 줄은 값 부분을 빼면 글자 단위로 같아야 한다.
- **비교 결과의 머리줄과 내용은 같은 글자로 시작할 수 있다.** 내용이 `++ `로 시작하는 줄을 추가하면 비교 결과에서는 `+++ `가 되어 파일 머리줄과 구별되지 않는다. 파서가 머리줄로 보고 건너뛰었다. 파서에 "지금 머리 구간인가, 내용 구간인가"라는 상태를 두었다.
- **이름으로 식별하면 이름을 바꿀 때 식별이 풀린다.** 봇을 로그인 이름으로만 알아보면, 봇의 이름을 바꾸는 순간 봇의 PR이 사람의 PR로 취급돼 제한이 조용히 사라진다. 이름이 바뀌어도 그대로인 계정 번호로도 판정한다.
- **PR을 연 사람과 PR에 커밋을 올린 사람은 다를 수 있다.** 검사는 PR을 연 계정으로 봇을 가렸다. 그런데 봇은 저장소에 쓰기 권한이 있으므로 **사람이 연 PR의 브랜치에 커밋을 올리고 그 PR을 머지할 수 있다.** 작성자는 사람이니 검사는 제한 없이 통과한다. 이벤트를 일으킨 계정도 함께 보게 했고, 애초에 봇이 정해진 이름의 브랜치에만 쓸 수 있게 저장소 규칙을 하나 더 만들었다.
- **측정하기 전의 비용 추정은 환경 하나의 값이다.** 자기검사는 작업용 PC에서 한 시간이 걸려 "태스크를 닫을 때 한 번만"이라는 규칙을 만들었다. 같은 검사가 CI 러너에서는 3분이었다(프로세스를 만드는 비용이 운영체제마다 크게 다르다). 규칙의 전제가 사라졌으므로 규칙도 바꿨다 — 로컬은 영향 받는 부분만, 전체 판정은 CI.

## 선택과 대안
| 질문 | 택한 것 | 버린 것과 이유 |
|---|---|---|
| 운영 승격 PR을 누가 여는가 | 당분간 사람이 연다(자동화는 검증 뒤 브랜치까지만) | 봇이 연다 — 봇의 PR은 봇이 머지할 수도 있고 승인이 필요 없다. 사람만 통과시킬 수 있는 관문이 생기기 전에는 운영 변경을 봇에게 열 수 없다. **목표는 봇이 열고 사람은 승인만 하는 것**이고, 관문을 실측한 뒤 바꾼다 |
| 넘겨받은 검사 후보의 범위 | 보증과 관련된 것만 이 태스크에, 나머지는 후속 위치와 완료 조건을 적어 넘김 | 전부 — 검사 확장 태스크가 된다 · 연결만 — 계약이 이 태스크로 미룬 항목이 다시 밀린다 |
| 교차 이력 대응 | 검사에서 공통 조상 개수 확인 + 저장소 규칙으로 선형 이력·스쿼시 전용 | 검사만 — 방어가 한 겹이고, 주 브랜치에 머지 커밋이 생기면 정상 봇 PR도 실패한다 |
| PR 가로채기 대응 | 브랜치 쓰기 제한 + 이벤트 발신자 판정 | 한쪽만 — 쓰기 제한은 설정이 풀리면 끝이고, 발신자 판정은 PR이 열리기 전에 끼워 넣은 커밋을 보지 못한다 |
| 자기검사 실행 시점 | 주 브랜치 push에서 항상 · PR은 검사나 워크플로를 바꾼 경우만 | 매 PR — 봇의 개발 배포마다 3분이 더해진다 · 주 브랜치에서만 — 검사를 망가뜨린 PR이 머지된 뒤에야 드러난다 |
| 도구 설치 방법 | 버전 고정 + 체크섬 대조를 워크플로 안에 직접 | 설치용 서드파티 액션 — 믿어야 할 대상이 하나 늘고, 저장소의 설치 스크립트는 봇이 바꿀 수 있다 |

## 결과와 검증
- 봇 제한 검사를 단독으로 돌리는 모드를 만들고, 독립 리뷰가 임시 저장소로 실험해 찾은 우회 경로(교차 이력 · 머리줄 모양의 줄 · 고정값 줄의 삭제와 이동 · 서브모듈과 변환 필터)를 닫았다. 새 자기검사 케이스는 수정 전에 실패하는 것을 먼저 확인했고, 기존 분기를 지키는 케이스는 분기를 한 줄씩 바꾼 변이로 고유성을 확인했다.
- 기존 동작은 바뀌지 않았다 — 긍정 픽스처에서 변경 전 스크립트와 출력이 바이트 단위로 같다.
- 저장소 규칙 둘을 적용하고 값으로 대조했다. 관리자 자격의 push에 원격이 "규칙 위반을 우회했다"고 답해, 규칙이 그 브랜치에 실제로 걸려 있음을 확인했다.
- 워크플로를 연결한 PR이 러너에서 두 번 통과했다: 전체 검사 약 30초 · 자기검사 122개 약 3분 · 작업 전체 약 4분.

## 다음 학습
- 봇의 자격으로 실제로 시험해야 확정되는 것이 남았다: 허용되지 않은 브랜치에 대한 push 거부, 봇이 사람의 PR에 커밋을 올렸을 때의 이벤트 값. 봇의 키는 운영자만 가지므로 첫 자동 배포와 승격 실연에서 증거를 남긴다.
- 사람만 통과시킬 수 있는 승인 관문이 필수 검사 안에서 동작하는지 실측한다. 되면 승격 PR을 봇이 열게 바꾼다.
- 자기검사를 건너뛰는 경로는 러너에서 아직 돌지 않았다(지금까지의 PR이 전부 검사나 워크플로를 바꿨다).

## 사고·오류
- **작업 도중 PC가 업데이트로 재부팅됐다.** 구현을 맡긴 작업이 끊겼지만, 커밋된 것은 전부 원격에 있었고 끊긴 작업은 단계별 로그를 남기고 있어 어디까지 했는지 바로 확인할 수 있었다. 이후의 작업에는 단계마다 로그를 남기게 했다.
- **오전에 권한 결정을 "계약 충돌의 해소"로만 설명했다.** 운영 승격 PR을 사람이 열게 한 결정은 영구적인 선택이 아니라 승인 관문이 생기기 전까지의 임시 형태였는데, 그렇게 말하지 않았다. 사용자가 목표 운영 방식을 다시 물은 뒤에야 "무엇이 임시이고 무엇이 유지되는지"를 표로 정리했다. 결정을 권할 때는 그것이 최종 형태인지 거쳐 가는 형태인지를 함께 말한다.
- **검토를 맡긴 작업이 금지한 실행을 한 번 했다.** 수정안을 확인하다 필터를 넓게 줘 전체 검사가 돌았고 공개 스키마를 내려받았다. 스스로 보고했고 추적 파일 변경은 없었다.
- **문서에 넣으려던 조건이 실제와 달랐다.** push 이벤트에도 "이벤트를 일으킨 계정"은 있다. 그 값을 그대로 넘기면 검사가 "작성자 없이 발신자만 왔다"며 실패한다. 스크립트로 두 경우를 돌려 보고서야 알았고, PR 이벤트에서만 넘기게 했다.

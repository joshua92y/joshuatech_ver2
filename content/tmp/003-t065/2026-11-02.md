# 003-platform-foundation T065 — copier 템플릿 생성물을 테스트로 먼저 못박기: 생성 배치·의존성 소스·빌드 컨텍스트가 한 묶음인 이유 (2026-11-02)
> 1일차(설계 · 계약 보정 · 빌드 · 리뷰). 짝 구현(T072)이 이 테스트를 초록으로 만든다. 결과·검증 절은 마감 때 채운다.

## 문제
템플릿으로 찍어낸 pod가 "수정 없이" 테스트·이미지 빌드·배포 매니페스트 검사를 통과한다는 것을, 템플릿이 아직 비어 있는 지금 테스트로 못박아야 했다. 생성 → 의존성 동기화 → 생성물 테스트 → arm64 이미지 → kustomize 렌더 → kubeconform → 매니페스트 단언 열여덟 가지를 하나의 하네스로 묶으면서, 아직 정해지지 않았던 것 — 생성물이 공용 라이브러리를 어떻게 참조하는지, 이미지는 어디서 빌드하는지, 하네스는 어디서 돌아가는지 — 를 함께 결정해야 했다.

## 배운 개념
- **의존성 소스 · 생성 위치 · 빌드 컨텍스트는 하나의 결정이다.** 공용 라이브러리를 uv 워크스페이스 멤버로 참조하면 멤버 밖에 생성한 샘플은 아예 풀리지 않고, 생성 시점의 `uv lock`이 루트 잠금을 바꿔 CI의 `--locked` 설치를 흔든다. 상대 경로 소스로 바꾸면 "pod는 `apps/<pod>`, 라이브러리는 두 단계 위 형제"라는 배치 하나만 지원하게 되고, Docker 빌드 컨텍스트는 그 둘을 다 담는 저장소 루트가 되어야 한다. 세 가지가 서로를 결정하므로 하나만 따로 고르면 나머지가 깨진다.
- **하네스는 실제 배치를 재현한다.** 임시 디렉터리에 미니 저장소(`apps/sample-pod` + `packages/django-common` 복사본)를 만들어 생성·동기화·빌드를 그대로 돈다. 가짜 플래그나 경로 치환으로 우회하면 템플릿이 실제 배치에서 깨지는 것을 놓친다.
- **uv는 멤버 밖 프로젝트를 독립 루트로 다룬다.** 워크스페이스 루트 아래에 있어도 `members`에 없으면 "project is not included"를 기록하고 자기 잠금 파일을 만든다 — 스크래치에서 실측으로 확인했고, 하네스와 생성 pod 모두 이 성질 위에 선다.
- **copier는 저장소 루트가 아닌 템플릿 경로를 작업 트리로 읽는다.** 경로가 git 저장소 루트인지 판정해 아니면 clone·태그 선택 없이 디렉터리를 그대로 쓴다. 덕분에 미커밋 변경을 바로 시험할 수 있지만, 답변 파일에 커밋이 남지 않아 `copier update`는 쓸 수 없다 — 연구 메모의 "별도 템플릿 저장소" 가정과 다른 점을 계약에 솔직하게 적었다.
- **도구 부재는 skip이 아니라 실패다.** Docker·kustomize·kubeconform이 없으면 "빨강"이 도구 때문인지 템플릿 때문인지 구분이 안 된다. 도구 검사 테스트를 따로 두어 먼저 초록을 증명하고, 본 테스트는 skip 없이 실패한다.
- **매니페스트 단언은 헬퍼 + 골든 + 변이로 판별력을 증명한다.** 템플릿이 없으니 실제 렌더로는 단언 코드를 검증할 수 없다. 계약을 그대로 만족하는 합성 렌더(골든)와 변이 스무 개 남짓으로 "각 검사가 자기 변이만 잡는다"를 지금 초록으로 증명한다 — 골든은 구현자에게 기대 모양의 거울이기도 하다.
- **지우는 경로는 자기가 만든 것뿐.** 생성 트리를 보존하는 환경변수를 받더라도 표식 파일이 있는 디렉터리만 비운다 — 임의 디렉터리를 지우는 테스트 하네스는 사고의 씨앗이다.

## 선택과 대안
- **독립 프로젝트 vs 워크스페이스 멤버**: 독립(자기 잠금 · 상대 경로 소스). 멤버는 샘플 생성과 CI 잠금 안정성 둘 다에서 걸렸다. 되돌릴 수 있게 사용자 확인 항목으로 표기했다.
- **미니 저장소 복사 vs 경로 치환 변수**: 복사. 템플릿에 테스트 전용 변수를 더하지 않고 실제 배치 그대로 검증한다.
- **생성물 테스트 결과 파싱**: 요약 줄 정규식 대신 junit XML 집계 — 실패·오류·skip 수를 결정적으로 읽는다.
- **골든 YAML 파일 vs 코드 안 문자열**: 파일. 구현자가 읽고 따라갈 수 있고, CI 경보선의 스캔 범위(`template/`) 밖에 둔다.

## 결과와 검증
- 신규 파일 13(하네스 `pyproject.toml` · 잠금 파일 · 테스트 모듈 7 · 헬퍼 3 · 골든 렌더 1 · 약 3,500줄). 잠금은 패키지 25개가 전부 PyPI에 sha256 해시로 고정됐고 직접 의존은 pytest · copier · pyyaml 셋뿐이다.
- 빨강: 생성물 검사 18개 중 4개 FAIL(생성 트리 · pyproject · env 예시 · copier 설정 — 전부 "파일이 없다") + 14개 ERROR(앞 단계 산출물이 없어 동기화·빌드·렌더 명령을 아예 돌리지 않는 가드) · exit 1. 빨강 단계에서 Docker · kustomize · 네트워크는 쓰이지 않는다.
- 인프라 초록 155: 도구 6(copier · uv · buildx arm64 · kustomize · kubeconform · 현재 템플릿으로 생성 자체는 성공) + 렌더 헬퍼 71(골든 1 · 변이 68 · 표 완전성 · 동치 표기) + 트리·해석 헬퍼 78(pyproject 골든+변이 25+표기 4 · env 7 · 마이그레이션 테스트 본문 골든+변이 4+표기 1 · copier 설정 5+9+1 · 트리 3 · 출력 해석 5 · 표식 가드 11). 변이마다 "맡은 검사만 잡는다"를 단언해 교차 오탐이 없음을 증명했다.
- 리뷰 2렌즈: 계약·문면 렌즈 approve_with_fixes(medium 2 · low 9 — 문면 조각 ↔ 테스트 대응표 전부 일치 · 계약 값 전부 일치 · 근거 없는 추가 0) · 실행 안전·위생·공급망 렌즈 approve(low 6 — 삭제 경로 7곳 전부 가드 안 · 하위 프로세스 규율 · 잠금 전부 PyPI sha256 · 3일 숙성 충족). 고친 것 8: 골든 Ingress `/session`을 Prefix로(Exact면 `/session/check`가 404 — 골든은 구현자의 참고 모양이라 중요) · 테스트가 고정한 계약 밖 가정 10개를 파일 머리에 "T072 가정"으로 모음 · `makemigrations --check`의 `--check`까지 단언(헬퍼 + 변이 4) · 식별 실패 문구에 "있던 것"을 보여 줌 · 런타임 시크릿에 owner URL이 `secretKey`로 들어오는 꼴도 위반 · 생성물 `uv run`에 `--locked` · 생성물 pytest 호출에 `--tb=short` 방어선 · 문서 세 곳에 "보존 경로의 상대 경로는 저장소 루트 기준".

## 사고·오류
- 지시문에 "`.gitignore`의 `tests/fixtures/generated/`는 깊이 무관"이라고 적었는데 틀렸다 — 패턴에 `/`가 있으면 루트 고정이다. 빌더가 `git check-ignore -v`로 반증하고, 보존 경로의 상대 경로를 저장소 루트 기준으로 푸는 설계로 고쳤다. 사실은 명령으로 확인하고 적는다.
- 빌더가 "빈 생성물에서 `uv sync`를 돌리면 uv가 상위 디렉터리의 저장소 워크스페이스를 잡아 루트 환경을 동기화한다"는 위험을 발견해 단계 가드를 넣었다 — 설계가 놓친 것이다. 상위를 탐색하는 도구(uv · git · pytest rootdir)는 "대상이 없을 때 무엇을 잡는가"를 먼저 묻는다.
- Bash 도구에서 CR을 세는 `grep -c $'\r'`가 빈 패턴으로 풀려 모든 줄을 셌고, `cat -A | grep '^M'`은 한글 UTF-8 바이트의 `M-^M` 표기와 겹쳐 거짓 양성을 냈다. 바이트 검사는 `od -An -tx1 -v`로 16진수를 세거나 파이썬으로 한다.
- 비밀 스캔 도구에 경로 두 개를 한 번에 주었더니 저장소 전체(가상 환경 포함 약 500 MB)를 훑어 의존 라이브러리의 시험 키를 "누출"로 보고했다 — 경로는 하나씩 준다.

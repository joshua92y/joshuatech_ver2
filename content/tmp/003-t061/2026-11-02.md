# 003-platform-foundation T061 — 아직 없는 모듈의 API를 테스트로 먼저 못박기: outbox 발행·릴레이·DLQ·동시성 (2026-11-02)
> 1일차이자 마감(설계 · 빌드 · 리뷰 1라운드 · 수정 · 커밋). 짝 구현(T069)과 스키마(T067)가 이 테스트를 초록으로 만든다.

## 문제
도메인 쓰기와 같은 트랜잭션에 이벤트 행을 남기고(outbox), 별도 릴레이가 그 행을 Kafka로 내보내는 패턴을 공통 라이브러리가 제공해야 한다. 테스트를 먼저 쓰려니 발행 함수의 시그니처(계약에 있다)뿐 아니라 릴레이를 한 번 돌리는 진입점, 실패를 주입할 틈, 지표를 읽는 방법 같은 **계약에 없는 이름**들을 정해야 했다. 또 "Kafka에서 봉투를 받아 스키마를 통과시킨다"는 문면은 스키마 파일이 아직 없는 상태에서 어떻게 테스트가 되는지도 정해야 했다.

## 배운 개념
- **계약에 없는 이름은 가정으로 표시하고 인계한다.** 설정 이름, 릴레이 진입점(`relay_once` → 결과 데이터클래스), 프로듀서 프로토콜(produce/flush/poll + 전송 콜백), 지표 모듈과 레지스트리 이름을 테스트 모듈 머리와 시험 설정에 "구현 과제가 확정한다"고 적어 두었다. 구현 과제는 이 테스트를 초록으로 만들면서 그 이름을 받아들이거나, 바꾸면 테스트도 함께 바꾼다.
- **스키마 검증은 실제 토픽으로.** 가짜 토픽을 쓰면 검증할 스키마가 영원히 없다. 실제 SP-1 토픽 하나(세션 폐기 이벤트)를 시험 토픽으로 쓰고, 봉투 스키마와 토픽 데이터 스키마 파일을 저장소 경로에서 읽되 없으면 **실패**(skip 아님)하게 했다. 스키마 과제가 선행이라는 사실이 테스트에 드러난다.
- **fake는 전송 계층만 바꾼다.** 프로듀서 대역은 선택·갱신·DLQ 분기 같은 릴레이 논리를 우회하지 않고 네트워크만 대신한다. 빌더는 대역이 실제 클라이언트 라이브러리의 오류 객체와 메시지 객체를 그대로 넘기게 만들었다 — 실제 라이브러리는 실패 때도 메시지 객체를 콜백에 넘기기 때문이다. 실제 브로커 경로는 따로 한 테스트(발행 2건 수신)와 인프라 스모크가 덮는다.
- **"동시 실행 중복 없음"은 SKIP LOCKED의 증명이 아니다.** 두 릴레이가 동시에 50행을 나눠 처리해 합이 50이고 중복이 없어도, SKIP LOCKED 없이 FOR UPDATE만 써도(기다렸다가 처리) 같은 결과가 나온다. 빌더가 테스트를 하나 더 두었다: 다른 트랜잭션이 행 둘을 쥔 채 릴레이를 돌려 **기다리지 않고** 나머지 셋만 처리하는지 본다.
- **경계값은 계약으로 읽는다.** 과제 문면은 "10 초과", 계약은 "attempts ≥ 10이면 DLQ". 테스트는 계약(10번째 실패에서 같은 패스 안에 DLQ)을 따르고 그 편차를 문서화했다. 문면과 계약이 어긋나면 계약을 따르고 적는다는 규칙이 다시 작동했다.
- **"UUID만, slug 금지"는 부정 경로가 있어야 고정된다.** 값이 UUID와 같다는 단언만으로는 slug를 넘기는 코드가 통과한다. 리뷰가 잡아 계약에 "UUID로 파싱되지 않으면 사용 오류"를 보강하고 음성 테스트를 추가했다. 같은 이유로 "요청 컨텍스트 A 안에서 인자로 B를 넘기면 오류"(심층 방어)도 계약·테스트에 넣었다 — 소비자 투영으로 교차 테넌트 오염이 번지는 코드 실수 경로를 라이브러리가 막는다.
- **테스트 프레임워크의 뒷정리와 잠금.** 릴레이 구현이 멈춰 스레드가 행 잠금을 쥔 채 남으면, 테스트 종료 시 테이블 비우기(TRUNCATE)가 그 잠금을 무한히 기다린다. 시험용 소유자 연결에 잠금 대기 상한(30초)을 두어 멈춤이 유한한 실패로 바뀌게 했다.
- **시그니처도 검사한다.** 키워드 전용 인자는 모든 호출을 키워드로 써도 고정되지 않는다 — `inspect.signature`로 종류를 확인하고 위치 인자 호출이 `TypeError`인지 본다.
- **시험 컨테이너 라이브러리의 Kafka 이미지는 태그에서 버전을 파싱한다.** digest로 핀하면 KRaft 모드 검사가 깨져 태그로 핀하고 digest는 주석에 남겼다. 이미지가 데이터 경로를 VOLUME으로 선언하므로 익명 볼륨 정리를 위생 검사에 넣었다(전 24 → 후 24).
- **실 Producer 객체는 비어 있으면 falsy다.** `__len__`이 큐 길이를 돌려주므로 `producer or make()` 같은 코드는 주입된 프로듀서를 버린다 — `is None`으로 판정해야 한다. 구현 과제에 인계했다.
- **릴레이는 저장된 봉투 바이트를 그대로 보낸다.** 전송 단계에서 시각이나 id를 다시 만들거나 SDK로 재직렬화하면 "수신 값 == 저장 값" 단언이 깨진다. 오래된 연구 메모(발행 표시 컬럼 갱신·필드 분해 저장)와 계약(성공 시 삭제·봉투 전체 jsonb)이 어긋났고 계약을 따랐다.

## 선택과 대안
- **실제 토픽 vs 가짜 토픽**: 실제 토픽. 스키마 검증이 실제가 되고 소스 이름도 실제 pod가 된다.
- **대역 프로듀서 vs 라이브러리 몽키패치**: 명시적 `producer=` 주입. 테스트가 프로토콜을 문서화하고 구현이 그것을 따른다.
- **잠금 대기 상한 vs TRUNCATE 권한 부여**: 상한. 앱 역할의 권한을 운영보다 넓히지 않는다.
- **DLQ 이름**: 규칙 파일 두 곳이 `<pod>.dlq`만 적어 dev 접두 규약(계약·지난 과제의 정정)과 어긋났다. 규칙을 계약에 맞췄다 — 구현 과제가 규칙만 읽고 틀린 이름으로 발행하는 사고를 막는다.
- **키워드 전용·시각 형식 같은 세부**는 테스트로 고정했다. 느슨한 단언은 구현의 자유가 아니라 계약 위반을 숨긴다.

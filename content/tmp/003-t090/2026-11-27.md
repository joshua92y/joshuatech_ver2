# 003-platform-foundation T090 — 콘텐츠 로더 구현: 시험을 고치지 않고 48을 통과시키며 라이브러리 기본값과 싸우기 (2026-11-27)
> 11-26 조사 · 11-27 설계 확정 · 빌드 · 리뷰를 함께 담는다. 세션은 11-26에 시작해 압축을 세 번 거치며 이어졌다. tick은 이 기록과 같은 커밋이다.

## 문제
- T086이 시험 48개로 고정한 계약대로 노트 사이트의 콘텐츠 로더를 만들어야 했다. 조건은 시험 파일과 픽스처 12 디렉터리를 하나도 고치지 않는 것이었다.
  - 모듈 넷: `schema.ts`(zod 프런트매터) · `mdx.ts`(파싱 · 본문 거부 규칙 · 컴파일) · `loader.ts`(스캔 · 교차 파일 규칙 · 오류 모음) · `index.ts`(공개 표면).
  - 과제 문면에 있는 것: `glob` 스캔 · 다국어 접미사 묶기 · `React.cache` 1회 · remark/rehype(Shiki) · `getCollection(name, {lang, includeDrafts})` · JSON Schema 내보내기.
- 노트 파일은 `.mdx`지만 본문은 순수 Markdown + GFM이다(T086-e). 원시 HTML · `import`/`export` 줄 · 중괄호 식 · 허용 밖 URL이 있으면 빌드가 실패해야 한다.
- 저장소가 공개라 CI 로그도 공개다. 오류 객체 · stderr · 경고 어디에도 입력 값(URL · 프런트매터 값 · 원문 줄 · YAML 별칭 이름)이 나가면 안 된다.
- 새 의존은 사용자 승인을 받은 정확 판 12개(+ dev 2)뿐이다. lock은 사전 해석본과 바이트까지 같아야 한다.

## 배운 개념
- **라이브러리 기본값이 설계 문장을 조용히 뒤집는다.** 이번 과제에서 셋을 만났다.
  - zod 4.6.7: 스키마에 `.regex()`를 붙이면 내보낸 JSON Schema에서 url의 `format: "uri"`가 사라진다. 그러면 JSON Schema만 보는 소비자는 공백 · 제어 문자가 든 URL을 받는다. → `.meta({ format: 'uri' })`로 되살렸다.
  - yaml 2.9.1(경고): `parse()`는 경고를 `process.emitWarning`으로 보내 원문 줄과 키를 stderr에 찍는다. → `parseDocument` + `logLevel: 'error'`로 경고를 모아 거부 사유로 쓴다. `'silent'`은 여러 문서 오류까지 지워서 쓰지 않는다.
  - yaml 2.9.1(태그): `version: '1.2'` + `schema: 'core'`를 줘도 `resolveKnownTags` 기본값이 참이다. 그래서 YAML 1.1 태그(`!!set` · `!!timestamp` · `!!binary` · `!!omap` · `!!pairs`)가 경고 없이 Set · Date · Buffer로 풀렸다. 「YAML 1.2 core · 모르는 태그 = 오류」를 지키려면 `resolveKnownTags: false`를 적어야 한다. 이 구멍은 변이 검사의 생존 변이를 파다가 나왔다.
- **mdast 노드에는 position이 없을 수 있다.**
  - GFM 자동 링크 리터럴은 두 단계로 만들어진다. 토크나이저가 거절한 꼴을 mdast 변환이 나중에 링크로 만들면(닫히지 않은 `[` 뒤 · `"` 바로 뒤의 `www.`) 새 링크와 쪼개진 text 노드에 position이 없다. `node.position.start.line`을 읽는 코드는 그 자리에서 던진다.
  - 해법: 앞선 위치 있는 형제의 끝 점에서 출발해, 사이 text의 줄 끝마다 다음 줄 1열, 그 밖 글자는 UTF-16 code unit마다 열 + 1로 센다(micromark와 같은 단위). 결과는 가장 가까운 위치 있는 조상의 끝 줄에서 자른다. 열은 issue 정렬에만 쓴다.
- **설계 주장은 실물로 확인한다.**
  - 설계 초안의 「산문 `xmpp:a@b.c` → 자동 링크 → 거부」는 설치 판에서 거짓이었다. 토크나이저가 이메일 부분을 먼저 mailto 링크로 만들고 `xmpp:`는 text에 남긴다.
  - 시험 기대값을 쓰기 전에 실제 remark로 탐침해서 바로잡았다. T086 기대값 30행은 전부 일치했다.
- **보안 판정은 파싱 전 원 문자열로 한다.**
  - URL 파서는 공백 · 탭 · 역슬래시를 정규화한다. 그래서 원 문자열에 공백 · 제어 문자 · `\`가 있으면 먼저 거부하고, http(s) URL의 userinfo(`user:token@host`)도 거부한다(프런트매터 · 본문 모두).
  - zod `httpUrl`은 hostname이 도메인 이름 꼴인지까지 본다(localhost · IP 거부 — 아래 「계약 문장」 참고). 그런데 공백 · 제어 문자는 받는다. 원 문자열 규칙이 따로 있어야 하는 이유다.
- **정렬은 Ordinal로 한다.** `localeCompare`는 로캘과 ICU 판에 따라 바뀐다. 파일 · issue 순서는 코드 단위 비교로 정한다.
- **오류 객체 규율**: issues 배열과 각 issue를 얼린다. `cause`는 없다. 자기 속성 키는 issues · name · message · stack으로 고정하고, message에는 파일 · 필드 · 규칙 이름만 싣는다.
- **파생 사본에는 신선도 가드를 둔다.** JSON Schema는 zod에서 만든 사본이다. 시험이 커밋된 파일과 재생성 결과를 바이트로 비교하고, 실패 메시지에 재생성 명령을 싣는다.
- **계약 문장은 검사가 하는 만큼만 약속한다.**
  - 설계와 규칙 문서는 출처 URL의 host를 「공개 도메인 이름」이라 적었다. 실제 판정은 zod `domain` 꼴 검사(점이 있는 이름 + 영문 최상위 라벨)뿐이다. 그래서 `*.local` · `*.internal` · `*.home.arpa` 같은 내부 이름이 그대로 통과했다.
  - 문구를 실제 판정대로 고치고 「내부 이름은 손으로 뺀다」를 적었다. 특수 용도 TLD를 막는 새 규칙은 계약을 바꾸는 일이라 따로 정하기로 했다.
- **결정은 그 결정이 적용되는 층에서 시험한다.**
  - 「본문 규칙은 모든 컬렉션에 돈다」는 결정이 있었는데, 시험은 검증 함수를 blog 이름으로 직접 부르는 것뿐이었다. 로더가 blog · projects에서 검증을 건너뛰는 변이가 살아남았고, 그 변이에서는 `javascript:` 링크가 HTML로 나갔다. 로더 경로에서 정확한 issue를 단언하는 사례를 더했다.
  - 비슷하게, 줄 계산 규칙을 CRLF로만 바꾼 사례는 다른 규칙(조상 끝 줄에서 자르기)에 가려 차이를 못 냈다. 셋째 줄을 붙여야 변이가 드러났다.
- **색 환경 변수는 판정을 흔든다.**
  - 환경에 `FORCE_COLOR`가 있으면 vitest 요약 줄이 ANSI 색 코드와 섞여 나와, 통과한 실행을 실패로 판정했다. 판정 전에 CSI 시퀀스를 지운다.
  - 이를 확인하다가 하나를 더 찾았다. `NO_COLOR`와 `FORCE_COLOR`가 함께 있으면 Node가 색 깊이를 잴 때 「NO_COLOR를 무시한다」는 경고를 stderr에 찍는다. 그래서 「자식 프로세스 stderr 0」 단언이 우리 코드와 상관없이 깨졌다. 둘 중 하나만 있을 때는 경고가 없어서, 조합을 바꿔 가며 자식을 띄워 보고서야 원인이 보였다. 시험이 띄우는 자식의 env에서 `FORCE_COLOR`를 지웠다.
- **변이 검사는 시험만이 아니라 코드도 판다.**
  - 설계에 변이 78행(바꿀 결정 → 잡아야 할 시험)을 미리 적고, 저장소 밖 사본 100개에서 99개 변이를 돌렸다.
  - 생존한 변이 하나를 분석하다가 원본의 known tag 구멍이 드러났다. 동등 변이 셋은 근거(차등 탐침 수백 회 — 차이 0)를 남겼다.
  - 동등 사례: 같은 slug의 파일이 `S.en.mdx` < `S.ja.mdx` < `S.mdx` 순으로 스캔되는데, 이 순서가 우연히 lang 순(en < ja < ko)과 같다. 그래서 translations 정렬을 지워도 결과가 같다.

## 선택과 대안
- **`React.cache` 1회 → 모듈 메모**(사용자 결정 〔90-1〕): 로더는 Next 렌더 밖(Node 생성 단계)에서 돈다. 그래서 React 캐시 대신 모듈 수준 Map(키 = 해석된 root · 컬렉션)을 쓴다. react 의존은 0이고, 코드 주석이 과제 문면과 잇는다.
- **`glob` → `readdir(withFileTypes)`**: 정규 파일만 읽고 심볼릭 링크는 따라가지 않는다(`not-regular` 오류). 숨김 파일 · 대소문자가 다른 `.mdx`도 이름 위반으로 잡는다.
- **sources 원소 = strict 객체 하나 + zod 밖 규칙**(union 아님): 처음 근거였던 「union이면 url 오류가 위로 올라간다」는 zod 4.6.7에서 사실이 아니었다(갈래가 하나 남으면 그 issue를 그대로 낸다). 그래도 union이면 source-kind · 빠진 title이 `invalid` 하나로 뭉개지므로 결정은 그대로 두고 근거만 고쳤다.
- **known tags 차단**: 1.1 태그 이름을 차단 목록으로 막는 대신 `resolveKnownTags: false`로 라이브러리의 스키마 경계를 그대로 쓴다. 이름 목록은 판이 바뀌면 낡는다.
- **JSON Schema `format` 되살림**: `.meta` vs `toJSONSchema` `override` — 산출이 같아 짧은 쪽(`.meta`)을 골랐다.
- **url host의 특수 용도 TLD**: 거부 목록(`.local` · `.internal` · `.home.arpa` …)을 바로 넣지 않고 문구만 실제 판정대로 고쳤다. 막는 규칙을 더하면 계약이 바뀌므로 사용자가 정할 일이다. 마감 보고에 알림으로 올린다.
- **네트워크 금지 정적 가드**: 리뷰가 제안한 넓은 정규식(따옴표 안의 `http` · `net` 같은 이름 어디서나)은 src의 URL 스킴 집합(`'http'` · `'https'`)에서 거짓 양성이 났다. 그래서 가져오기 자리(`from` · `import` · `import()` · `require()`)로 좁혔다. 템플릿 리터럴 동적 import는 놓친다(받아들인 한계).

## 사고·오류
- 설계 워크플로의 판정 정규식이 굵은 표기 `**MEDIUM**`을 놓쳐 r2 단계가 한 번 건너뛰어졌다. 정규식을 고쳐 같은 run을 이어서 돌렸다(앞 단계는 캐시).
- 대화 압축 뒤 워크플로 스크립트 경로가 거부됐다(그 도구가 돌려준 경로만 받는다). 스크립트를 저장소의 gitignore 자리로 옮겨 그 경로로 띄웠다.
- 하위 에이전트 넷(빌드 둘 · 리뷰 둘)이 금지된 Bash `cd`를 썼다(파일 변경 0 · 자진 신고).
- 리뷰 고침 빌더가 변이를 저장소 작업 트리에 제자리로 넣고 해시로 되돌렸다. 새 파일이 아직 untracked라 git으로 되돌릴 길이 없는 상태였다. 재확인이 잔여 0을 확인했고, 다음 빌더 지시는 사본에서만 돌게 했다.
- 설계 시험 예시에 사설 대역 주소를 적었다가 문서용 대역(RFC 5737)으로 바꿨다. 공개 저장소에서는 실제 내부 주소와 겹칠 수 있는 값을 쓰지 않는다.

# 003-platform-foundation T077 — 시험 먼저, 자격 없이: Playwright 로그인 · 세션 폐기 시험을 빨강으로 세우고 비밀이 새는 길을 막기 (2026-11-23)
> T077 · T079(Playwright)와 T078(플랫폼 하네스)을 한 설계로 진행한 첫날이다. 같은 날 정한 UD-13 정비 결정(Argo CD 판 올림 시점 · Traefik 경로)도 이 기록에 둔다. T077 · T079는 닫혔고, T078은 운영자 창에서 라이브를 관찰한 뒤 닫는다.

## 문제
- US4(신원 · 인가)의 시험을 구현보다 먼저 써서 「올바른 이유로」 실패하는 것을 보여야 했다. 그런데 이 시험들은 자격이 있어야 끝까지 갈 수 있다.
  - e2e 사용자의 비밀번호 · TOTP는 Vault에 있다.
  - 교환 · 폐기 시험은 BFF client 비밀을 전제한다.
  - 자격을 언제부터 다룰지, 자격 없이 무엇을 증명할 수 있는지를 먼저 정해야 했다.
- 저장소에는 Playwright 실행 기반이 없었다. 게다가 브라우저 시험 도구는 실패하면 많은 것을 디스크에 남긴다. trace(요청 · 응답 헤더와 본문), HTML 리포트(입력 값), 실패 문맥 파일(코드 · 페이지 스냅숏)이다. 나중에 실제 비밀이 들어올 길을 지금부터 막아 둬야 했다.

## 배운 개념
- **빨강은 「도달 → 자격」 순서로 짜면 자격 없이 관찰할 수 있다.**
  - 지금 빨강의 올바른 이유는 「인증 서비스가 아직 없다」다.
  - 시험이 먼저 인증 호스트에 닿는지를 보고 프록시 기본 404 서명과 일치하면 `[gate] … until T080`으로 멈추게 했다. 그러면 Vault 자격을 한 번도 읽지 않고 빨강을 볼 수 있다.
  - 자격 단계에서 멈추면 「잘못된 이유」다.
- **도구의 「가리기」 옵션을 믿기 전에 공식 API를 확인한다.**
  - Playwright의 `mask`는 스크린샷 전용이다. trace에는 값을 가리는 설정이 없다.
  - 1.65.1은 시험이 실패하면 출력 디렉터리에 오류 · 코드 프레임 · 페이지 스냅숏을 담은 문맥 파일을 쓴다(실측).
  - 그래서 가리는 대신 기록 자체를 끄고, 그 설정을 실행 때 덮지 못하게 했다. 막은 것: CLI 플래그 · 파일 단위 `test.use()` · 환경 변수.
- **「hits 0」은 양성 대조가 있어야 증거다.** 비밀이 새는지 보는 바늘 시험은 두 실행이다.
  - 실행 1: 값을 일부러 실패 경로에 흘려 「아무 면에서도 0」을 본다.
  - 실행 2: 감싸개 없이 같은 경로를 밟아 「그 면에서 실제로 잡힌다」를 본다.
  - 대조 없이 0이 나오면, 그 경로가 막힌 것인지 스캔이 못 보는 것인지 구분되지 않는다.
- **「완료」 판정은 결과 화면으로 한다.**
  - 로그아웃 페이지에 도착했다는 것으로 끝을 판정하면 빈 PASS가 된다. Playwright의 URL 대기는 URL이 이미 맞으면 바로 돌아오고, 실제 로그아웃은 그 뒤의 API 호출에서 일어난다.
  - 그래서 완료 = 로그인 화면의 입력 칸이 보이는 것으로 바꿨다.
- **파일을 지워도 세션은 죽지 않는다.**
  - 저장된 로그인 상태 파일을 지우는 것만으로는 서버 세션이 무효가 되지 않는다.
  - 그래서 정리 단계를 「서버 로그아웃 → 죽은 상태 확인 → 파일 삭제」로 묶었다.
  - 이전 실행의 잔여 파일은 다른 가드보다 먼저 세어 노출 의심 신호를 남긴다.

## 선택과 대안
- **S-01 문장 개정 시점(사용자 결정)**
  - 「시험 작성 전」과 「첫 자격 실행 전」 중 뒤를 골랐다.
  - 까닭: 빨강 확인에 자격이 필요 없다. 그리고 규칙 개정 리뷰는 실물 자격 블록을 봐야 하는데, 그 블록은 인증 서비스 배포 뒤의 사실에 기댄다.
- **T079 측정 경로(사용자 결정)**
  - 과제 문면의 서비스 토큰 직접 호출은 신원 관문(CN)이 거부 목록보다 먼저라 늘 403이다.
  - 그래서 BFF 프록시 경로(로그아웃 전 쿠키 사본으로 1초 뒤 401)를 골랐다. tester에게 자격을 더 주지 않는다.
- **Playwright 위치(사용자 결정)**
  - 권고는 별도 워크스페이스 패키지였다. 사용자는 루트 devDependency를 골랐다.
  - 대신 판을 정확히 핀하고, lockfile 변화 범위(새 패키지 정확히 셋)를 검사하고, 브라우저는 헤드리스 셸만 받았다.
- **커밋 단위**
  - 수정 라운드에서 T077 · T079가 공통 lib를 함께 쓰게 되어, 둘을 한 커밋으로 묶었다(나누면 앞 커밋의 자기 시험이 빨강이다).
  - T078은 따로 커밋했다.
- **UD-13(같은 날 결정)**
  - Argo CD는 다음 패치(14일 원칙 충족 시점)를 기다려 한 번에 올린다. 그 사이 알려진 취약점은 저장소 쓰기 권한을 전제하고, 정적 검사 금지 규칙이 막는 꼴이다.
  - 프록시(Traefik) 보안 패치는 K3s 자동 업그레이드를 기다리되, 인증 서비스 공개 · ForwardAuth 첫 사용 전에 판 관문을 둔다.

  - 자식 프로세스 env 이름은 허용 목록 그대로였다(자격 · 클러스터 설정 0).
  - 잔여 파일 · 잠금 표식 · 산출물은 0이었다.
- **과제 체크**: 84/119(T077 · T079). T078은 운영자 창의 라이브 관찰 뒤다.

## 사고·오류
- **「건드리지 않는다」고 말한 옛 브라우저가 지워졌다.**
  - Playwright가 설치하면서 쓰이지 않는 옛 브라우저를 자동으로 정리했다. 설치 전 안내에서 그 기본 동작을 확인하지 않았다.
  - 다음에는 도구가 설치 때 지우는 것이 있는지 먼저 본다.
- **정렬 규칙을 말과 다르게 계산했다.**
  - 브라우저 디렉터리 목록 해시를 「Ordinal 정렬」이라고 적고 실제로는 문화권 정렬로 계산했다가 다시 계산했다.
  - 나중에 다른 프로그램이 재계산할 값은 규칙을 코드와 글에서 같은 이름으로 고정한다.
- **지시문의 숫자를 잘못 읽었다.** 설계의 「live 1 · live 3」을 과제별 수로 읽어 수정 지시에 「live 4」라고 썼다. 실제로는 누적 수였다. 수정자가 짚었다.
- **Node 결함**: Windows에서 한글 경로의 파일 하나를 지우는 비재귀 삭제가 조용히 실패하거나 프로세스를 죽였다. 수정자가 실측하고 다른 API로 바꿨다.

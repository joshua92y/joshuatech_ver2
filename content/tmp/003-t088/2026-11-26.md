# 003-platform-foundation T088 — 번들 예산 시험 먼저: gzip 합산과 2,621,440 bytes 경계를 변이로 고정하기 (2026-11-26)
> 11-23 ~ 11-26을 함께 담는다. 설계 11-23 ~ 24 · 빌드 11-24(T086 시험과 한 빌더). 그날 세션은 수정 라운드 도중 주간 사용 한도로 끊겨 기록을 남기지 못했다. T088 시험은 수정 라운드에서 바뀌지 않았고, 11-26 재개 뒤 빨강을 다시 관찰했다. tick은 이 기록과 같은 커밋이다.

## 문제
- 서버 번들 gzip ≤ 2.5 MiB 게이트(T093)를 세우기 전에, 측정 스크립트 `bundle-budget.mjs`의 계약을 시험으로 먼저 고정해야 했다.
  - 과제 문면: dry-run 산출 디렉터리 픽스처의 gzip 합산 · 2,621,440 bytes 초과면 exit 1 · 이하면 0.
- 시험이 살 패키지가 아직 없었다(`apps/web` 스캐폴드는 T091). → ⓪ 기반에서 최소 매니페스트(`@jt/web` · `test` = `vitest run` · 기존 vitest 5.0.5 재사용 · lock 차이는 importer 줄뿐)를 먼저 커밋했다.

## 배운 개념
- **경계는 양쪽을 다 찍는다.**
  - `judge(2_621_440)` 참 · `judge(2_621_441)` 거짓. CLI도 시험이 따로 계산한 합 S에 대해 `--limit S` → exit 0 · `S − 1` → exit 1.
  - 한쪽만 보면 `<`와 `<=`를 가리지 못한다.
- **무작위 바이트는 gzip으로 줄지 않는다.**
  - 초과 사례는 2,700,000 B 무작위 `.bin`을 실행 중에 만든다. 압축 뒤에도 한도를 넘으므로 픽스처를 커밋하지 않고도 「초과」를 만들 수 있다.
  - 기대 gzip 크기는 시험이 level 9로 따로 계산한 독립값이다.
- **부재 단언은 양성 단언과 짝이어야 한다.**
  - 「import만으로 CLI가 돌지 않는다(`import.meta.main`)」만 보면 던지는 스텁도 통과한다 → 「직접 실행하면 요약 줄이 나온다」를 짝으로 둔다.
  - 한도 상수도 CLI 기본 출력 `limit_bytes=2621440`과 짝이다.
- **pnpm 필터가 어긋나면 exit 0이다(리뷰 C-2).**
  - `pnpm --filter <없는 이름> exec …`은 `No projects matched the filters`를 내고 exit 0으로 끝난다.
  - 설계의 확인 명령에 `--fail-if-no-match`가 없어 「전부 통과 · exit 0」이 빈 초록과 구별되지 않았다. → 증거는 이 플래그를 붙인 꼴과 끝 요약 줄로 적는다.
- **규칙 글롭의 범위가 에이전트마다 다르다(C-8).**
  - Claude는 `.claude/rules/infra.md`의 `paths: scripts/**`를 중첩된 `apps/web/scripts/`에도 맞춰 주입했다.
  - Codex 라우터(AGENTS.md 표)는 같은 행을 루트 `scripts/**`로 읽는다. 지금은 무해하다.

## 선택과 대안
- **측정 단위**: 파일마다 gzip level 9를 더한다(재귀 · 정렬 · 링크 미추적). 대상은 `.js` · `.mjs` · `.wasm` · `.bin`이고 `.map`은 뺀다(실물 확인은 T093).
- **CLI 꼴**: stdout은 ASCII 요약 한 줄 · exit 0/1/2. 사용 오류(디렉터리 없음 · 대상 0 · `--limit` 꼴 오류)는 2이고, stderr는 오류 토큰 한 줄이라 경로가 실리지 않는다.
- **한도 값은 문면 그대로**
  - 근거였던 「Workers Free 3 MiB 한도의 안전 마진」은 Workers 압축 크기 한도 폐지(2026-09-04)로 낡았다. 조사는 2.5 MiB를 시작 시간 예산으로 유지할 만하다고 봤다.
  - 값을 바꾸면 새 ADR과 시험 수치가 따르므로 T091 전에 사용자에게 여쭌다.

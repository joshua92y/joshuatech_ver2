# 003-platform-foundation T048 후속 — "없음"과 "알 수 없음"은 다르다: 커널 시험 도구의 모듈 판정 마무리 (2026-10-07)
> 후속 작업 2일차(3라운드 구현 → 준수 리뷰 → 보강 → 실제 kmod 리뷰 → 마무리 → 커밋 → 두 노드에서 새 판으로 상태 읽기). 과제 자체는 어제 닫혔고, 이것은 인계 표의 첫 항목이다.

## 문제
어제 리뷰가 찾은 구멍은 "별칭이 풀린다고 기능이 있는 것은 아니다"였다. 오늘은 그 수정(계승자 규칙)을 구현하고, 실제 커널 패키지로 다시 공격하고, 남은 틈을 닫아 커밋하는 날이다. 사용량 한도로 빌더가 두 번 끊겨 세 번째에 끝났다.

## 배운 개념
- **계승자 규칙.** 별칭 a는 새 커널에서 풀리는 것만으로는 부족하다. 풀린 모듈 가운데 하나가 새 커널에서 a를 스스로 선언해야 하고, 그 모듈이 지금 커널에 같은 이름으로 있으면서 이미 a를 선언하던 형제여서는 안 된다. 실제 6.17 → 7.0 트리에서 이 규칙이 대체됨으로 센 짝은 다섯이고, 리뷰어가 하나씩 보아 전부 진짜 교체였다. 다음 실제 전환(7.0의 다음 패치 커널)에서는 이름으로 못 찾는 모듈이 0개였다.
- **"없음"과 "알 수 없음"은 다르다.** 형제 확인은 지금 커널에 그 이름의 모듈이 있는지 묻는다. 처음 구현은 조회가 어떤 이유로든 실패하면 "없다 = 새 모듈"로 읽었다. 그러면 지금 커널 트리가 손상됐을 때 형제가 새 모듈로 보여 잘못된 대체됨이 난다. 도구가 내는 "그 이름 없음" 문구만 "없음"으로 받고, 다른 실패는 세지 않게 바꿨다. fail-closed의 뜻은 "모르면 안전한 쪽"이다.
- **다른 프로그램의 파서를 흉내 낼 때는 그 프로그램으로 잰다.** 부팅 시 모듈 목록은 systemd가 커널 명령 줄을 어떻게 나누느냐에 달렸다. systemd는 따옴표 밖의 공백에서 낱말을 나누고, 따옴표는 어디에 있든 벗기되 따옴표 안의 공백은 낱말을 잇는다. 셸의 `read -a`는 따옴표 안의 공백에서 먼저 잘라 뒤에 쉼표로 이어진 모듈을 놓쳤다. 50가지 모양을 systemd-modules-load로 직접 돌려 같은 결과가 나오게 맞췄다.
- **변이 시험은 테스트의 공백을 드러낸다.** 준수 리뷰어의 변이 20개 가운데 7개가 살아남았고, 그중 4개는 통과 쪽으로 열리는 방향이었다. 코드는 옳았지만 그 판단을 지키는 테스트가 없었다. 살아남은 변이마다 죽이는 사례를 넣었다. 한 변이는 "이름 검사가 종류 검사를 가린다"는 이유로 첫 사례 집합에서 살아남았고, 종류만 다른 객체를 따로 만들어야 죽었다.
- **같은 도구로 노드를 읽어 닫는다.** 커밋한 판을 운영자가 두 노드에 파이프로 넘겨 상태만 읽었다. 옛 판이 "없음 1개"로 적던 6.17 커널 줄이 "없음 0 · 대체됨 1"로 바뀌었다. 도구 변경의 효과를 실제 노드에서 확인하는 데 쓰기는 0이었다.

## 선택과 대안
| 질문 | 택한 것 | 버린 것과 이유 |
|---|---|---|
| 맨 이름 별칭과 공유 별칭 | 계승자 규칙 하나 | 암호 별칭만 막는 특례 — 공유 별칭(소켓 계열)은 그대로 남는다 |
| 조회 실패의 처리 | "그 이름 없음" 문구만 없음으로, 나머지는 세지 않음 | 모든 실패를 없음으로 — 손상된 트리에서 잘못된 통과 |
| 명령 줄 낱말 나누기 | systemd와 같은 규칙을 직접 구현 | 따옴표 글자만 지우기 — 따옴표 안 공백에서 잘려 뒤 모듈을 놓친다 |
| 끊긴 빌더의 결과 | 해시로 상태를 판정하고 이어서 돌림 | 처음부터 다시 — 이미 리뷰받은 결과까지 버린다 |

## 결과와 검증
- 하네스 160 → 235 단언(214회 실행, 약 4.5–5분). 리뷰 셋(준수 · 실제 kmod 둘)의 변이 40여 종이 전부 죽었다.
- 실제 트리 실측: 노드가 겪은 전환(6.17 → 7.0)의 판정은 그대로다(없음 하나, 대체됨 셋). 반대 방향도 그대로다. 손상된 트리와 따옴표 모양의 잘못된 통과 둘은 수정 뒤 사라졌다.
- 두 노드에서 새 판으로 읽은 상태: 둘 다 OK, 6.17 줄 "없음 0 · 대체됨 1". 쓰기 0.
- 운영 문서 §6에 모듈 검사 절차(정확한 목록으로 수용 · 전부 받아들이는 옵션은 쓰지 않음), update-grub 직후 패키지 작업 복구 순서, 부팅 폴백 서비스 확인을 넣었다.

## 다음 학습
- 이름 검사 자체도 같은 성질이 있다(다른 모듈의 정규화된 별칭으로 통과). 지금 트리에서는 0건이라 다음 라운드 후보로 남겼다.
- 가족 별칭(여러 모듈이 선언하는 별칭)의 새 구성원을 계승자로 세는 것은 설계 한계로 적어 두었다. 노드의 모듈에는 그런 별칭이 없다.

## 사고·오류
- **빌더가 두 번 끊겼다.** 한 번은 인증 세션 만료, 한 번은 사용량 한도. 시작 전 해시 확인 덕에 두 번 다 "손대기 전"임을 바로 확인했다.
- **지시와 다르게 한 것이 보고됐다.** 한 빌더가 한국어 파일을 sed로 한 번 고쳤다. 결과는 깨끗했지만 규칙 위반이라 다음 지시에 금지 문구를 다시 넣었다.

# 003-platform-foundation T087 — hello E2E 시험 먼저: 「도달 확인 → 단언」으로 자격 없이 빨강을 보고 값 없이 관찰하기 (2026-11-26)
> 11-23 ~ 11-26을 함께 담는다. 설계 11-23 ~ 24 · 빌드 11-24. 그날 세션은 수정 라운드 도중 주간 사용 한도로 끊겨 기록을 남기지 못했다. 11-26에 재개해 수정 · 검증을 마치고 런처로 빨강을 다시 관찰했다. tick은 이 기록과 같은 커밋이다.

## 문제
- 웹 앱 첫 화면(T090 · T091 · T092)이 서기 전에, 사용자 시점 E2E `e2e/hello.spec.ts`를 써서 「앱이 없어서」 실패하는 것을 보여야 했다.
  - 과제 문면: `/ko` · `/en` · `/ja` 200과 노트 2편 · `/` 302(Accept-Language) · `/ja` 「번역 없음」 배지 · 페이지 응답 `Set-Cookie` 0 · 디자인 토큰 3계층 · `/api/health` · `x-request-id` · 로드 뒤 30 s 프리페치 ≤ 10.
- T077이 세운 Playwright 기반(아티팩트 0 · 값 출력 0 · static-gate)과 부딪혔다. 프리페치를 세려면 요청 리스너가, 토큰을 보려면 `evaluate`가, 헤더를 보려면 헤더 API가 필요한데, 모두 값을 출력 면으로 실어 나를 수 있다.
- 빨강의 이유가 「서버가 없다」 하나여야 했다. 쿠키 0 · 배지 0 같은 부재 단언은 서버가 답하지 않으면 공허하게 참이다.

## 배운 개념
- **「도달 확인 → 단언」 순서면 빨강에 자격이 필요 없다.**
  - 모든 시험의 첫 단계가 `/ko`에 닿는지 본다. 루프백 연결 거부 + 웹 스캐폴드(`apps/web/next.config.ts`) 없음 → `[gate] site-absent until T091`로 멈춘다. 스캐폴드가 생긴 뒤의 거부는 `[env] site-server-not-running`으로 갈린다.
  - 예외는 로컬 `/api/health` 하나다. 상류 identity-admin이 없어 판정은 prod(T095) 몫이라, 도달 전에 값 없는 INFO를 내고 skip한다.
  - 부재 단언은 도달(앱 표식 확인) 뒤에만 의미가 있다.
- **값을 싣는 API는 막고, 수만 돌려주는 탐침 한 파일만 예외로 둔다.**
  - static-gate가 `allHeaders(` · `headerValue(` · `headerValues(` · `headersArray(` · `postData` · `.response(` · `requests(` · `consoleMessages(` · `pageErrors(` · `existingResponse(`를 어디서나 금지한다. 규칙마다 심은 양성 대조가 있다.
  - `request` 리스너와 `evaluate`는 `e2e/lib/site-probe.ts`만 쓴다. 반환은 수 · 불리언뿐이고 URL은 읽지 않는다. 이 파일을 import할 수 있는 곳도 hello.spec과 브라우저 자기 시험 둘로 묶었다(템플릿 리터럴 지정자까지 — 리뷰 B-5).
  - `expect(` 인자에 `headers` · `.body` · `cookies(`가 들어가면 위반이다. 실패 메시지가 값을 찍기 때문이다.
- **허용 근거가 사실과 다르면 근거를 고치고, 새 근거를 단언으로 고정한다(리뷰 B-6).**
  - 「`headers()`는 쿠키를 빼고 돌려준다」는 브라우저 Request/Response에만 맞다. APIResponse의 `headers()`는 set-cookie를 이어 붙여 돌려준다.
  - 실제 방어선은 http.ts 감싸개(값 없는 오류) · emit-args · expect-args다. 주석을 고치고 두 규칙의 값 출처를 단언 두 줄로 고정했다. 고치기 전에는 그 출처를 지우는 변이가 살아남았다.
- **도구 동작은 실측한다.**
  - 새 APIRequestContext는 `accept-language`를 싣지 않는다 → `/` 302 사례 표가 넣은 헤더 그대로 판정된다.
  - chromium에서 해석할 수 없는 커스텀 속성의 계산값은 빈 문자열이다 → 토큰 「모두 해석됨」 판정이 성립한다.
- **중계되지 않는 실패는 런처 앞에서 막는다.**
  - 설정 로드 중의 throw는 Playwright 오류 줄이라 런처 끝 줄에 `failed=-1`만 남았다.
  - → 런처가 대상(BASE_URL · 모드)을 먼저 검사해 값 없는 `[guard] site-target-not-allowed`로 exit 2. `site` 모드의 exit 0에는 passed ≥ 1을 더했다(빈 초록 방지).
- **수집 실패는 사례별 원인을 가린다.**
  - 첫 빨강은 lib 파일 부재로 수집이 통째로 실패했다(`0 passed, 1 failed`).
  - 빈 모듈 둘을 잠시 두어 사례별 원인(`169 passed, 41 failed`)을 본 뒤 구현했다.

## 선택과 대안
- **대상 허용 목록**: local은 루프백 origin만, prod는 공개 apex 정확히 하나, 그 밖은 값 없는 가드다. preview는 Access 뒤라 자동 대상이 아니다. 빨강 관찰은 루프백만 쓴다(이 묶음은 공개 호스트 요청 0).
- **h-7 prod `degraded`(리뷰 A-2 → 컨트롤러 결정)**
  - 계약이 `ok` · `degraded`를 모두 유효로 정했고 인수 기준은 「200 중계」다. → degraded도 PASS이고 값 없는 `INFO health-status degraded` 한 줄을 낸다. 엄격하게 두고 편차로 기록하는 길은 쓰지 않았다.
  - 계약 밖 status는 여전히 `[product]`다(반복 단언 — status 검사 자체를 지우는 구현을 잡는다). degraded 갈래의 실행 관찰은 T095 몫이다.
- **B-6 쿠키 상수**: T079의 계약 이름 상수를 `__Host-jt_session` · `__Host-jt_csrf`로 바꿨다(tick 뒤라 t077 정정 노트에 적는다). 바늘 시험의 자리값 `jt_session=`은 계약 이름을 단언하지 않아 그대로 둔다(바꾸면 바늘 재실행 비용만 든다).
- **e2e 규칙 파일**: `.claude/rules/e2e.md`(+ KR) · AGENTS.md 라우팅 행 · codex-parity 목록 · agent-layer 하네스 RULES · MIRRORS를 한 커밋에 넣는다. 하나라도 빠지면 라우팅 · 규칙 시험이 빨강이다. agent-layer 단언은 72 → 79. run-all의 미러 쌍 목록(001의 고정 9쌍)은 건드리지 않았다.

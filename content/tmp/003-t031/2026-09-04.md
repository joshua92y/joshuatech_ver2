# 003-platform-foundation T031 — 읽기 전용 자격으로 클러스터를 단언하는 테스트를 구현보다 먼저 쓰기 (2026-09-04)
> 백필: 2026-09-17 작성(런북 §3·커밋 기록·설계 문서 기반).

## 문제
US2(K3s 클러스터·GitOps·정책)의 첫 task는 구현이 아니라 검증 코드였다. 헌법 II의 테스트 우선 규칙을 살아 있는 인프라에 적용하려니 세 가지가 동시에 걸렸다.

첫째, 검증 대상이 함수가 아니라 클러스터다. 단위 테스트처럼 입력을 만들어 넣을 수 없고, 이미 배포된 객체를 읽어 계약과 대조하는 것만 할 수 있다. 둘째, 검증 주체가 읽기 전용이다. 이 저장소의 계약은 에이전트·tester·CI에게 ServiceAccount `agent-view` 자격만 준다 — `view` 집계에 추가 ClusterRole과 일부 네임스페이스의 `pods/portforward`를 더한 것으로, **Secret `get`도 `exec`도 없다**. 셋째, T031이 단언하려는 형상의 상당 부분이 한참 뒤 phase에서야 생긴다(정책 Job은 T041, CA 미러는 T056, 앱 pod는 T075, 메트릭 수집기는 T098). 아무것도 없는 시점에 전부 FAIL로 두면 매일 돌리는 `tests/run-all.ps1`이 영구히 빨갛고, 반대로 없으면 통과로 두면 테스트가 거짓 증거를 만든다.

## 배운 개념
**자격이 단언의 형태를 결정한다.** 쓸 수 있는 동사가 `get`/`list`/`watch`/`logs`/`port-forward`/`auth whoami`/`auth can-i`뿐이면, "무엇을 확인할까"가 아니라 "이 동사들로 무엇을 증명할 수 있나"에서 설계가 출발한다. 자격을 넓히는 쪽이 늘 더 쉽지만, 그러면 테스트 하네스가 침해 표면이 된다.

**fail-closed를 두 계층으로 나눈다.** SKIP 판단은 러너(`run-platform-tests.ps1`)의 게이트에만 있다. `KUBECONFIG`가 없으면 "실행했을 파일 목록"을 찍고 exit 0으로 빠지고, 있으면 `kubectl auth whoami`로 컨텍스트 사용자가 `agent-view`인지 먼저 단언한다(admin kubeconfig면 실행 거부). 본체의 단언은 스스로 "환경이 없어서 통과"하는 경로를 갖지 않는다 — 클러스터 도달 실패·JSON 파싱 실패·예외는 전부 FAIL이다. 개발 PC에서 초록인 이유는 게이트가 통째로 비켜서서지, 단언이 관대해서가 아니다.

**단계별 SKIP 게이트와 공허 PASS는 정반대다.** 게이트는 "미래 산출물이 아직 없다"를 명시적으로 표시하고(`SKIP ca-1: until T056`), 산출물이 나타나는 순간 곧바로 엄격 판정으로 바뀐다. 공허 PASS는 "검사 대상이 0개라서 통과"다. 후자는 회귀를 못 잡는데 초록이라 더 위험하다.

**직접 볼 수 없으면 원인 쪽을 본다.** `agent-view`는 Secret을 못 읽으니 CA 미러에 `ca.key`가 없다는 것을 Secret 자체로는 확인할 수 없다. 대신 그 Secret을 만드는 ExternalSecret의 spec을 단언한다 — `dataFrom` 부재, `remoteRef.property: ca.crt`, `secretKey: ca.crt`, template `data` 키 제한, `templateFrom` 부재, `mergePolicy` 미사용, store 이름. `auth can-i`로 권한을 물어 두 경로를 분기시켰다.

**이름만 보는 대조는 뚫린다.** AppProject `namespaceResourceBlacklist`를 kind 이름으로만 보면 다른 API group의 동명 kind로 만족될 수 있다. group까지 대조하되 `*`는 허용하고, 오퍼레이터 CRD는 group 접미 일치로 봤다(`cnpg.io`는 `postgresql.cnpg.io`와 플러그인 group을 함께 포함).

## 선택과 대안
**Vault seal 확인**: `exec` + vault CLI를 기각했다. `exec` 권한이 없고, 주자면 자격 경계가 무너진다. 채택한 것은 `port-forward` + `GET /v1/sys/seal-status`다 — 계약이 `agent-view`에 일부 ns의 `pods/portforward`만 남긴 이유가 이것이다. 로컬 포트는 운영자의 port-forward와 충돌하지 않게 빈 포트를 동적으로 잡고, try/finally로 정리한다.

**네임스페이스 내부에서 출발하는 네트워크 프로브**: pod를 만들 수도, 기존 pod에 들어갈 수도 없다. 셋으로 쪼갰다 — ① GitOps 안에 상주하는 assert Job(T041)의 성공 여부와 로그를 읽는다 ② 적용된 NetworkPolicy 객체를 읽어 정적으로 단언한다(허용 집합이 계약 매트릭스 안인지, ipBlock 규칙에 `ports`가 있는지, `except`가 IMDS·RFC1918 4종을 덮는지) ③ 남는 것은 항상 SKIP으로 두고 운영자가 1회 수동 프로브 후 출력을 첨부한다. 프로브를 위해 자격을 넓히는 안은 기각했다.

**프레임워크**: Pester를 도입하지 않고 저장소의 기존 tofu 테스트와 같은 자체 완결 구조로 갔다 — 한 줄 = 한 단언(`PASS|FAIL|SKIP <id>: …`), 마지막 줄에 집계. 단언 본문은 `(status, detail)` 두 값을 반환하고 래퍼가 배열의 **뒤에서 두 개**를 읽는다. PowerShell에서 본문의 우발적 파이프라인 출력이 앞에 섞여도 판정이 흔들리지 않게 하려는 장치다.

**러너에서 `KUBECONFIG`가 설정됐는데 파일이 없을 때**: SKIP과 FAIL을 저울질하다 FAIL로 정했다. 경로 목록은 지원하지 않고 파일 없음으로 본다. 같은 맥락에서 하위 디렉터리에 테스트 파일이 있으면 게이트보다 먼저 FAIL이다 — 평면 탐색이라 조용히 건너뛰어질 파일이 SKIP 경로에 숨는 것을 막는다.

## 결과와 검증
단언 48개로 닫았다: 게이트 3 + 노드 3 + Argo 4 + Vault seal 2 + ESO 3 + CA 미러 1 + 네임스페이스 2 + PSA 2 + 공통 정책 세트 5 + 조건부 정책 2 + NetworkPolicy 양방향 14 + 메트릭 수집 1 + 리소스 limit 2 + Reloader 1 + 백업 3. 이 가운데 운영자 수동 프로브 5개는 항상 SKIP이므로 PASS 후보는 43개이고, 단계별 SKIP 게이트는 7개(CA 미러 1 · assert Job 3 · 앱 pod 2 · 메트릭 수집기 1)다.

RED은 실제로 확인했다 — 클러스터가 없는 상태에서 모든 클러스터 단언이 사유와 함께 FAIL로 떨어지는 것을 보고 커밋했다. 리뷰는 `kubectl` shim에 가짜 JSON을 물려 단언을 한 항목씩 뒤집는 mutation 방식으로 했고, Major 1 + Minor 14가 나와 같은 날 반영했다.

리뷰 반영에서 바뀐 것 중 배움이 큰 것들: 메트릭 수집기 게이트를 "특정 종류의 특정 이름"에서 "이름 접미 또는 라벨로 워크로드 탐색"으로, `--all-containers`까지 붙여 사이드카 로그를 포함. 공허 PASS 2건에 양성 증거 하한 추가. blacklist group 대조와 CRD group 접미. DNS 정책은 포트뿐 아니라 도착 셀렉터(kube-system + kube-dns pod)까지. 네이티브 stdout/stderr를 반환 직전에 마스킹해 kubeconfig 경로·홈 디렉터리가 리포트에 남지 않게. 임시 파일은 프로세스 트리 kill + 종료 대기 후 재시도 삭제.

부수 산출물이 하나 더 있었다. 테스트를 쓰는 행위 자체가 계약의 내부 모순을 한 건 드러냈다(아래).

## 사고·오류
**계약 모순을 테스트가 찾아냈다.** 네트워크 정책 계약과 task 문면은 "앱 네임스페이스 pod에서 공개 리졸버의 443 연결이 실패해야 한다"고 적었는데, 같은 계약의 외부 egress 형식(전체 대역 + IMDS·RFC1918 4종 `except` + 443/TCP)과 허용 매트릭스대로라면 그 연결은 **성공해야** 한다. 형식과 매트릭스를 정본으로 보고, 프로브를 "리졸버의 53(허용 포트 밖) · 노드 사설 IP의 443(RFC1918 `except`) · IMDS의 80(`except`)은 실패 + 리졸버의 443은 성공(양성 대조)"으로 교체하는 안을 올려 사용자 결정(2026-09-04, 옵션 A)을 받았다. spec·plan·tasks와 계약은 승인된 불변 입력이라 문구 정정은 converge 경로로 미루고, 테스트의 SKIP 문구만 그 자리에서 고쳤다. 교훈: 테스트를 먼저 쓰는 것은 구현을 검증하기 전에 **계약의 일관성**을 검증하는 일이다.

**구현 전에 쓴 테스트가 미래 형상을 과대 명세했다.** 메트릭 수집기 단언은 처음에 "DaemonSet이 아니면 FAIL"로 종류를 고정했는데, 실제 T098 형상은 차트가 만드는 StatefulSet이다. 성질(스크레이프 오류 로그 0건)이 아니라 배치 형태를 단언한 것이 문제였다. 테스트는 계약이 실제로 요구하는 성질만 잡고, 구현 재량에 속하는 형태는 탐색으로 흡수해야 한다.

**공허 PASS 2건.** 외부 443 egress 단언은 "규칙마다 조건을 만족한다"만 봤기 때문에 그 규칙이 0개여도 통과했고, 백업 평문 검사는 목록이 비면 "평문 0건"으로 통과했다. 둘 다 양성 증거 하한(해당 규칙 ≥ 1, 오브젝트 ≥ 1)을 넣어 막았다. "빈 목록은 증거가 아니다"를 단언 문구에 적어 두었다.

**허용 집합에 자기 네임스페이스를 잘못 넣었다.** Vault 수신 허용 ns 목록에 vault 자신을 포함했는데, vault는 같은 네임스페이스 통신을 허용하는 정책 대상이 아니다. 계약 표를 다시 읽고 제거했다.

**Windows 런타임 함정 셋.** ① OCI CLI가 키 파일 권한을 Windows PowerShell 5.1로 검사하는데, pwsh 7이 상속시킨 모듈 경로 때문에 5.1이 보안 모듈을 못 읽고 실패한다 → 호출 동안만 그 경로를 빼고 finally에서 복원. ② 세션 토큰이 만료되면 CLI가 대화형 재인증을 물어 하네스가 멈춘다 → stdin을 빈 파일로 리다이렉트해 EOF로 즉시 중단(FAIL)시킨다. ③ 루프백 HTTP 호출이 시스템 프록시를 타지 않게 `-NoProxy`를 붙였다. 셋 다 "테스트가 사람을 기다리거나 조용히 오래 매달리지 않게" 하는 같은 원칙의 사례다.

**PowerShell 특유의 함정 둘.** 모든 문자열 비교를 ordinal 헬퍼로 통일했다(이 저장소는 이전 feature에서 문화권 의존 비교에 물린 적이 있다). 그리고 없는 배열 필드를 `@()`로 감싸면 원소 1개로 세어지는 문제 때문에, JSON 배열 접근은 전용 헬퍼를 통해서만 한다.

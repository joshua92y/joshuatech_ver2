# 003-platform-foundation T067 — 이벤트 스키마와 호환성 게이트: 검사기 자신은 누가 지키는가 (2026-11-03)
> 1일차(설계 · 계약 보정 · 빌드 r1 · 리뷰 r1 · 수정 r2 · 리뷰 r2). 2일차(r3 · r4 · 마감)는 `2026-11-04.md`.

## 문제
`packages/events`에 CloudEvents 봉투와 토픽 6개의 JSON Schema를 두고, PR이 스키마를 비호환으로 바꾸면 CI가 막아야 했다. 비교 검사기(`check-compat.mjs`)의 API는 앞선 태스크(T064)가 테스트로 먼저 못박아 두었다. 막상 만들려고 하자 두 가지가 걸렸다.

- 아직 소비자가 없는 SP-2 토픽 다섯 개는 계약에 필드 이름만 있었다. 그런데 스키마가 main에 들어가는 순간 필수 필드의 추가도 제거도 금지다. 지금 정한 필수 집합이 그대로 v1이 된다.
- 검사기도 저장소 안의 코드다. PR 쪽 검사기로 PR 스키마를 검사하면, 같은 PR이 검사기를 느슨하게 고쳐 자기 위반을 통과시킬 수 있다.

## 배운 개념
- **기준 쪽 검사기.** 기준(main) 커밋에 이미 있는 검사기로 비교하면, 같은 PR 안에서 검사기를 약하게 고치는 길이 막힌다. 이 검사기 사본은 패키지 밖 임시 디렉터리에서 돈다. 그래서 CLI 경로는 Node 내장 모듈만 import하고, 스키마 검증 라이브러리(ajv)는 처음 필요할 때만 지연 로드한다.
- **부트스트랩 조건은 좁을수록 안전하다.** "기준에 검사기가 없으면 이 변경의 검사기를 쓴다"로 두면 구멍이 생긴다. 검사기를 지운 PR이 한 번 머지되면, 다음 PR부터는 제 검사기로 돈다. 그래서 기준에 검사기도 스키마도 **둘 다** 없을 때만 부트스트랩하고, 스키마만 있고 검사기가 없으면 오류(2)로 끝낸다.
- **같은 러너에서 게이트보다 먼저 도는 PR 코드는 게이트를 바꿀 수 있다.** 테스트(vitest)는 PR 코드를 실행한다. 이것이 같은 job에서 게이트보다 먼저 돌면 많은 것을 바꿀 수 있다.
  - 게이트 스크립트 파일을 덮어쓴다.
  - git 객체 대체(`git replace`)나 `.git/info/attributes`를 심는다.
  - 다음 스텝의 환경 파일(`GITHUB_ENV`)에 값을 쓴다.

  게이트 job과 테스트 job을 나누었다.
- **`git archive`는 그 트리의 `.gitattributes`를 따른다.** `export-ignore` 한 줄이 머지되면 그 뒤 기준 꺼내기가 전부 빈다(실측). 기준은 `git ls-tree`와 `git cat-file blob`으로 꺼내고, 경로 성분을 하나씩 해석한다. 어떤 성분이 디렉터리가 아니거나 git이 실패하면 "없음"이 아니라 오류다(실측: `cat-file -t … || true`는 중간 성분이 심볼릭 링크일 때 rc 128을 "없음"으로 삼켰다).
- **실패를 통과로 읽지 않게 출력 계약을 둔다.** 검사기가 적재에 실패하거나 진입점 가드가 꺼진 채로 아무것도 출력하지 않고 0으로 끝나면, 게이트는 그것을 "위반 없음"으로 읽는다. 그래서 검사기는 요약 줄(`checked N · added M · violations K`)을 정확히 하나 찍는다. 게이트는 다음 조건이 하나라도 어긋나면 2로 끝난다.
  - K가 종료 코드와 맞는다.
  - stdout의 위반 줄 수가 K와 같다.
- **두 정규식 엔진은 같은 패턴을 다르게 읽는다.** 생산자 쪽은 ajv(JavaScript)로, 소비자 쪽은 Python `jsonschema`로 검증한다.
  - Python `re`의 `$`는 끝 줄바꿈 바로 앞에서도 맞는다.
  - Python의 `.`은 CR과 U+2028 · U+2029에도 맞는다.
  - `\d` · `\w`는 유니코드 숫자 · 글자까지 맞는다.

  그래서 패턴은 명시 문자 클래스만 쓰고, `.`을 쓰지 않으며, 끝 앵커는 `$(?!\n)`로 둔다(두 엔진 대조 53/53).
- **열린 스키마 원칙은 기계로 지킨다.** 소비자는 모르는 속성을 무시해야 한다. 그래서 `additionalProperties: false`는 기준 쪽 검사기가 오류로 막는다. 제한이 없던 속성에 `enum`이나 `const`를 새로 두는 것도 위반이다. 허용 값이 "모든 값"에서 몇 개로 줄기 때문이다(`enum-removed`로 본다).
- **enum 값 추가는 배포 순서가 있어야 안전하다.** 소비자는 data를 스키마로 검증하고, 실패하면 DLQ로 보낸다. 따라서 옛 스키마를 가진 소비자는 새 enum 값을 거부한다. 새 스키마를 담은 소비자가 먼저 배포되어야 한다.
- **"캐시 입력을 두지 않음"은 "캐시 없음"이 아니다(r2 리뷰).** setup-node v6.5.0은 `package-manager-cache`가 기본 켜짐이다. 작업 공간의 `package.json`이 npm을 가리키면 자동 캐시가 켜진다. 복원 경로는 체크아웃의 `.npmrc`가 고른다. 결국 같은 PR의 이전 실행이 저장해 둔 파일이 게이트 앞에 풀린다(고정 SHA 원문으로 확인).
- **체크아웃한 바이트는 커밋 blob과 다를 수 있다(r2 리뷰).** `.gitattributes`의 `ident` · `working-tree-encoding`은 작업 트리 바이트를 바꾼다. `git hash-object`는 필터를 적용해 blob과 같은 값을 내므로 차이를 숨긴다. `--no-filters`로 해시해야 바뀐 것이 보인다(실측).

## 선택과 대안
- **필수 집합**: 계약에 토픽별 필수 · 선택 · 타입 · 형식 표를 두고 지금 확정했다. 대안 "SP-2까지 비워 둔다"는 기각했다. 스키마 파일이 있어야 소비자 검증과 CI 게이트가 성립한다. 이 기능이 main에 머지되기 전까지는 기준에 스키마가 없어 전부 "추가"로 보이므로, 그때까지는 고칠 수 있다.
- **검사기 출처**: 기준 커밋의 검사기를 쓴다. 대안 "PR 쪽 검사기"는 같은 PR 안의 약화를 막지 못해 기각했다.
- **job 구성**: 게이트 job(체크아웃 · Node · 게이트 스크립트만)과 테스트 job으로 나누었다. 대안 "한 job에서 게이트를 앞에 둔다"는 기각했다. 설치용 캐시 복원(setup-node `cache`)이 여전히 게이트 앞에 남고, "게이트 job에서는 PR 코드 0"을 정적 단언 하나로 지키기 어렵다.
- **기준 꺼내기**: `ls-tree` + `cat-file blob`을 썼다. 대안 두 가지는 모두 기각했다.
  - `git archive`는 `export-ignore`를 따른다.
  - 기준 커밋 체크아웃은 기준 트리의 속성 변환을 그대로 받는다.
- **패턴**: 두 엔진 공통 부분집합(명시 클래스 · `$(?!\n)`)을 썼다. 대안 "엔진마다 다른 스키마"는 정본이 둘이 되어 기각했다.

- r1: 빌더 테스트 203개(T064 38 + 새 스키마 테스트 165)가 통과했다. 게이트 하네스는 55/0이었고, 변이는 전부 검출됐다. 리뷰 두 렌즈의 결과는 다음과 같다.
  - 계약 렌즈: medium 2 · low 7.
  - 보안 렌즈: high 1(같은 job의 PR 코드가 게이트를 무력화한다) · medium 2 · low 2.
- r2: job 분리 · 기준 꺼내기 재작성 · 출력 계약 · 검사기 규칙 · 패턴 규칙을 반영했다. 테스트 256 · 하네스 89/0 · 두 엔진 대조 53/53 · 변이 20 전부 검출. 리뷰 결과는 다음과 같다.
  - 계약 렌즈: low 6.
  - 보안 렌즈: high 1(setup-node 자동 캐시) · medium 1(작업 트리 바이트) · low 3.
- 실측으로 확정한 것:
  - `export-ignore` 한 줄로 기준이 빈다.
  - 중간 심볼릭 링크에서 rc 128이 난다.
  - Python `$` · `.`이 다르게 맞는다.
  - `ident` 체크아웃에서 필터 적용 해시는 blob과 같고, `--no-filters`만 다르다.

## 사고·오류
- r1 설계는 테스트를 게이트와 같은 job, 게이트 앞에 두었다. 과제 문면("job events-compat → T064 PASS")을 한 job으로 읽었기 때문이다. 리뷰 high로 job을 나누었다.

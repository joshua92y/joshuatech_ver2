# 003-platform-foundation T051 — 벽시계는 메시지 경로가 아니다: 이벤트 · 캐시 플랫폼 하네스 (2026-10-08)
> 1일차(2026-10-07 착수 · 10-08 완료). test-first 과제 — 구현(T055–T057)보다 먼저 쓴 검사이고, 지금 라이브에서는 FAIL이 기대값이다.

## 문제
US3의 나머지 반은 Kafka 클러스터 · 토픽 · 사용자 ACL과 인증이 걸린 캐시(Dragonfly) dev/prod 인스턴스다. 이 과제는 그것들을 조회 전용 자격으로 확인하는 하네스를 먼저 쓰는 것이다. 자격이 필요한 검사(produce/consume 왕복, 캐시 ACL 거부)는 클러스터 안 Job이 하고 하네스는 로그만 읽는다.

## 배운 개념
- **"5초 내 왕복"을 벽시계로 재면 영원히 실패한다.** 검사 Job의 컨슈머는 메시지를 받은 뒤에도 유휴 대기 20초가 지나야 끝난다. JVM 기동 두 번도 더해진다. 그래서 로그의 경과 초는 항상 20초를 넘는다. 수용 기준의 5초는 메시지 경로 기준이다. Job이 produce 시각과 consume 수신 시각의 차이를 밀리초 토큰으로 찍고, 하네스는 그 토큰(정확히 하나)으로만 판정하게 바꿨다. 토큰 형식은 두 과제 사이의 계약으로 적었다.
- **버전 사실은 문서가 아니라 실제 CRD로 확인한다.** 지시문에 적힌 API 판은 오래된 것이었다. 빌더가 실제 릴리스의 CRD를 읽어 v1만 서빙된다는 것, ACL의 작업 필드가 복수형이라는 것, 리스너 인증 방식의 열거값을 확인했다. 그 사실은 구현 과제가 쓸 매니페스트의 규칙이 됐다.
- **"실행 중"과 "준비됨"은 다르다.** 파드 phase가 Running이어도 컨테이너가 반복 재시작 중일 수 있다. Deployment의 Available 조건은 replicas가 0이어도 참이다. 같은 종류의 상태 조건이 둘 이상이면 어느 것을 믿을지 정할 수 없다. 셋 다 fail-closed로 바꿨다. Ready 조건까지 보고, replicas와 availableReplicas가 1인지 보고, 조건이 중복이면 모호함으로 FAIL한다.
- **인증 우회 경로를 하나씩 닫는다.** 캐시의 비밀번호가 인자가 아니라 환경 변수나 플래그 파일로 들어올 수 있고, Kafka의 superUsers에 사용자를 넣으면 ACL 검사가 무의미해진다. 선언에 없는 것은 전부 FAIL로 뒀다.
- **단위 테스트가 콘솔 코드 페이지에 묶이면 게이트가 환경을 탄다.** 사유 문구에 한글이 들어가자, 자식 출력을 콘솔 코드 페이지로 읽는 단위 테스트가 영문 콘솔에서 깨졌다. 하네스는 출력이 리다이렉트될 때 UTF-8로 쓰고 끝날 때 콘솔 설정을 되돌리며, 단위 테스트는 UTF-8로 읽게 했다. .NET이 출력 인코딩을 바꾸면 콘솔 자체가 바뀌고 자식이 끝난 뒤에도 남는다는 것을 실측했다.
- **변이 시험이 "코드는 맞지만 테스트가 안 지키는" 자리를 드러낸다.** 리뷰어가 만든 변이 36종 가운데 16종이 살아남았다. 하네스는 전부 옳게 판정했지만 그 판정을 고정하는 사례가 없었다. 그 사례들을 넣고, 바뀐 규칙마다 변이를 다시 만들어 전부 죽였다.

## 선택과 대안
| 질문 | 택한 것 | 버린 것과 이유 |
|---|---|---|
| 왕복 5초 판정 | Job이 찍는 메시지 경로 지연 토큰(정확히 하나) | 로그의 경과 초 — 컨슈머 유휴 대기 때문에 항상 실패 · "실측 뒤 재검토" — 성립할 수 없는 약속 |
| 리스너 · superUsers | 모든 리스너 TLS+인증, superUsers에 두 사용자 금지(지시보다 강함) | 지정 리스너 하나만 검사 — 인증 없는 리스너와 superUsers가 ACL 검사를 무력화한다 |
| 콘솔 인코딩 | 리다이렉트 시 UTF-8 + 종료 시 복원 | 콘솔 설정만 바꾸기 — 운영자 콘솔이 바뀐 채 남는다 |
| 단위 테스트 속도 | 지금은 느린 심 유지(약 10–15분), 컴파일 심은 세 하네스에 함께 적용(후속) | 이 과제에서만 바꾸기 — 세 하네스가 다른 심을 쓰게 된다 |

## 사고·오류
- **지시문에 없는 버전을 적었다.** 실제로는 존재하지 않는 Strimzi 판과 옛 API 판을 지시문에 적었고, 빌더가 실제 릴리스로 바로잡았다.
- **빌더와 리뷰가 세션 한도로 끊겼다.** 두 번째 세션에서 파일 상태를 확인하고 처음부터 다시 띄웠다.
- **빌더가 다른 빌더의 프로세스를 죽일 뻔했다.** 잘못된 PID로 종료 명령을 보냈지만 아무것도 종료되지 않았음을 확인했다. 동시 작업에서는 자기 프로세스만 이름 접두로 골라 정리해야 한다.

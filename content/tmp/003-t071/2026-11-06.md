# 003-platform-foundation T071 — 관측 모듈 1일차: 라이브러리 기본값이 무엇을 싣는지부터 센다 (2026-11-06)
> 1일차(설계 확정 · 1차 · 2차 구현과 리뷰 · 3차 결정 — 설치 소스 조사와 설계 초안은 11-05에 시작했다). 2일차(3차 결과 · 4차 · 5차 · 6차 · 7차 · 8차 · 9차 · 10차 · 마감)는 `2026-11-07.md`.

## 문제
pod 공통 라이브러리에 관측 모듈 둘을 만든다. T063이 먼저 써 둔 시험 21개를 통과시키는 것이 목표다.
- 로그: 한 줄에 JSON 객체 하나 · 요청 id · 비밀 키 마스킹.
- 트레이스: OpenTelemetry Django 계측 · 샘플링 0.1 · 헬스 경로 제외.
- 오류 보고: Sentry는 예외만 보낸다.
- 헬스: `/healthz`(프로세스만) · `/ready`(DB만) · `/health`(의존 셋을 병렬로 · 3초 안에 답한다).

과제 문장은 짧았다. 어려운 것은 「무엇을 남기지 않는가」였다. 라이브러리 기본값이 이미 많은 것을 싣고 있었고, 그것을 세는 데 하루가 갔다.

## 배운 개념
- **예외 렌더러의 기본값이 비밀을 싣는다.**
  - structlog의 `dict_tracebacks`는 기본으로 프레임 지역 변수를 싣는다(`show_locals=True`). DB 연결 문자열의 비밀번호 · Kafka 설정 dict가 그대로 JSON에 들어간다.
  - JSON 렌더러의 기본 폴백은 `repr`이다. 요청 객체 · 설정 객체가 repr로 찍히면 쿼리스트링과 헤더가 같이 나간다.
  - 그래서 예외는 지역 변수 없는 문자열(`format_exc_info`)로만 렌더하고, JSON으로 못 바꾸는 값은 `<타입 이름>`으로 바꾼다.
- **요청 id도 입력이다.**
  - django-structlog는 「상류 id를 믿는다」 설정이 켜지면 형식을 보지 않고 받는다.
  - 그래서 설정과 무관하게 꼴(`^[A-Za-z0-9._:-]{1,128}$`)을 보고 받는다. 꼴 밖이면 새 uuid를 만든다.
- **OpenTelemetry 계측의 기본값은 쿼리스트링을 span에 싣는다.**
  - Django 계측은 기본으로 `http.url` · `http.target`에 쿼리까지 넣는다. 응답 훅에서 그 속성의 쿼리를 뗀다.
  - 계측을 바꾸는 env가 여럿 있다: 요청 헤더를 span 속성으로 싣기 · 요청 객체 속성(`META` · `COOKIES`)을 `str()`로 싣기 · 새 semconv(`url.query`가 시작 속성이 된다) · SDK 끄기.
  - 리뷰 1차가 이 가운데 하나(요청 객체 속성 env)를 메모리 탐침으로 찔렀다. env 하나로 Authorization · Cookie 값이 span 속성에 실렸다.
  - 그래서 OpenTelemetry를 import하기 **전에** 그런 env를 이름만 실은 설정 오류로 거부한다.
- **import 때 굳는 값이 있다.**
  - 계측 미들웨어 클래스는 import 때 env를 읽어 클래스 속성에 굳힌다. 나중에 env를 지워도 늦다.
  - 그래서 계측한 뒤에도 굳은 값을 다시 확인한다. 어긋나면 계측을 되돌리고 기동을 멈춘다.
- **열거는 「어디까지 셌는가」를 적어야 닫힌다.**
  - 2차 리뷰가 거부 목록 밖의 env를 찾았다. API 패키지가 import 때 읽는 `OTEL_PROPAGATORS`다.
    - `none`이면 propagator가 비어, 계측이 None 문맥을 붙인다. 그 요청과 같은 스레드의 뒤 요청(liveness 경로 포함)이 500이다.
    - `baggage`뿐이면 상류 traceparent를 조용히 버린다.
  - 나는 계측 패키지와 SDK만 세고 API 패키지를 빠뜨렸다. 범위를 「설치된 opentelemetry-* 배포 전부」로 넓히고, 기준(요청 값을 싣는다 · 계측을 끈다 · 이어받기를 끈다)을 문장으로 적었다.
- **Sentry는 거부 목록보다 허용 목록이 닫힌다.**
  - 헤더를 지우는 목록은 새 헤더가 생길 때마다 뚫린다. 남길 헤더 다섯(host · user-agent · accept · content-type · content-length)만 남긴다.
  - 클라이언트가 보낸 `sentry-trace` · `baggage`는 이벤트의 trace 문맥과 envelope 머리를 정한다. trace 문맥은 pod가 기록 중인 span의 값으로 바꾸고, 동적 샘플링 문맥은 늘 지운다.
  - Redis 자동 통합은 거부 목록 조회 키(원문 사용자 id가 든 키)를 브레드크럼으로 싣는다. 자동 통합을 끈다.
- **헬스 검사는 서로를 막으면 안 된다.**
  - 검사마다 새 데몬 스레드로 돌리고, 전체 마감 2.5초가 지나면 그 스레드는 버린다.
  - 버린 스레드가 쌓이지 않게 검사 칸(`/ready`의 DB · `/health`의 db · Dragonfly · Kafka)마다 살아 있는 스레드를 8개로 묶는다. 칸이 차면 그 검사만 곧바로 fail이다.
  - 1차는 칸 하나를 모두 같이 썼다. 리뷰가 「`/health` 부하가 readiness를 내린다」를 찾았고, 2차에서 칸을 나눴다.
  - 스레드 풀은 고르지 않았다. 멈춘 의존이 일꾼을 붙잡으면 다른 검사까지 기다린다.

## 선택과 대안
- **django-health-check 대신 `SELECT 1`**: 그 패키지는 검사용 테이블을 만든다. 행 수준 보안(RLS) 허용 목록 검사가 그 테이블을 예외로 둬야 해서 고르지 않았다(과제 문장과 다른 편차 — 보고서 후보).
- **Sentry release = `<pod>@<git sha>`**: 과제 문장은 이미지 digest였다. digest는 빌드 뒤에 정해져 이미지 안에 구울 수 없다(편차 후보).
- **env를 덮어쓰지 않고 거부한다**: 위험한 env를 조용히 지우면 운영자가 낸 설정이 말없이 무시된다. 기동 실패가 조용한 열림보다 낫다.
- **마스킹은 닫힌 목록**: 「비밀처럼 보이는 이름」을 넓게 잡으면 `partition-key` · `idempotency-key` 같은 상관 값이 사라진다. 이 스택이 실제로 두는 비밀 이름과 일반 비밀 낱말의 변형만 지운다. 값 안의 비밀은 보지 않는다(호출자가 비밀을 로그 필드로 넘기지 않는다).

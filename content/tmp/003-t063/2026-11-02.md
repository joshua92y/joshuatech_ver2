# 003-platform-foundation T063 — 관측을 테스트로 먼저 못박기: JSON 로그 마스킹 · 분산 추적 상관 · 헬스 세 경로의 경계 (2026-11-02)
> 1일차이자 마감(설계 · 빌드 · 리뷰 1라운드 · 수정 · 커밋). 짝 구현(T071)이 이 테스트를 초록으로 만든다.

## 문제
pod 공통 라이브러리는 구조화 로그(요청 id 전달·생성, 테넌트 id, 추적 id, 민감 헤더 제거, 쿼리스트링 미기록), 분산 추적(샘플러 비율, 상류 `traceparent` 이어받기, 헬스 경로 제외), 헬스 세 경로(liveness는 외부 조회 없음 · readiness는 DB만 · 상세는 항상 200)를 제공해야 한다. 테스트를 먼저 쓰려니 "로그 한 줄에 무엇이 있고 무엇이 없어야 하는가"를 필드 단위로 정하고, 의존성 장애를 테스트 안에서 재현할 방법을 정해야 했다.

## 배운 개념
- **연구 메모와 계약이 어긋나면 계약을 따르고 이유를 적는다.** 연구 메모는 readiness에 헬스체크 라이브러리를 권했지만, 그 라이브러리의 DB 검사는 자기 테이블에 쓰기를 한다 — 테넌시 과제가 고정한 "RLS 없는 테이블은 허용 목록에 있어야 한다"는 검사와 충돌하고, 계약은 readiness를 `SELECT 1`로 못박았다. 테스트는 동작(200/503 · 외부 조회 없음)만 단언하고 라이브러리를 가정하지 않는다.
- **라이브러리 기본값을 소스로 확인한다.** 요청 id 미들웨어는 기본 설정에서 상류 `X-Request-ID`를 **믿지 않고** 새로 만든다 — 계약("헤더가 있으면 그대로")을 만족하려면 설정 하나를 켜야 한다. 또 요청 로그의 `request` 필드가 쿼리스트링을 그대로 담아 "쿼리스트링을 남기지 않는다"는 계약은 별도 processor가 필요하다. 둘 다 문서가 아닌 소스에서 봤다.
- **"제외 URL"은 정규식 검색이다.** 추적 라이브러리의 제외 판정은 절대 URI에 대한 정규식 search라 앵커 없는 `health`는 `/healthy-ping`을, `ready`는 `/already`까지 제외한다. 테스트는 `/obs/ready-check`가 **제외되지 않음**을 단언해 앵커 정규식을 강제한다.
- **장애는 설정이 아니라 연결에서 재현한다.** DB 다운은 Django 연결 객체의 접속 설정에서 포트를 닫힌 포트로 바꾸고 연결을 닫아 재현한다(연결 타임아웃 1초 → 드라이버가 2초로 올린다). 캐시·브로커 다운은 닫힌 포트 주소로, 또는 연결을 받자마자 끊는 리스너로.
- **연결 수 판정은 "지금 열린 것"이 아니라 "받은 횟수"로.** 캐시 서버의 연결 목록 id 차집합은 요청 안에서 열고 바로 닫은 연결을 놓친다(뒤 스냅숏에 그 id가 없다). 빌더가 참조 구현 변이로 이 맹점을 실측했고, 서버가 지금까지 받은 연결 수(INFO stats)의 전후 차이로 바꿨다 — 지난 과제의 같은 단언도 함께 고쳤다. 더 강한 증거는 "연결을 받자마자 끊고 수락 수를 세는 리스너"다: readiness와 liveness가 어느 의존에도 다이얼하지 않음을 시간·플랫폼과 무관하게 증명하고, 상세 헬스는 다이얼한다는 양성 대조까지 준다.
- **DB 드라이버는 실패 경로에서 비밀을 되비친다.** PostgreSQL 드라이버의 접속 함수는 인자 이름 하나를 비밀번호가 든 접속 문자열로 다시 묶는데, 테스트 러너의 긴 트레이스백은 마지막 프레임의 인자 값을 그대로 찍는다 — DB 접속 실패 한 번이 비밀번호를 출력에 남긴다(빌더의 변이 실측 · 일회용 컨테이너의 비밀). 테스트는 DB에 닿는 요청의 예외를 트레이스백 없이 실패로 바꾸고, 스위트 전역 기본을 짧은 트레이스백으로 바꿨다.
- **드라이버의 하한을 모르면 상한을 잘못 잡는다.** 같은 드라이버는 연결 타임아웃 1초를 2초로 올린다(libpq 관행). 세 의존이 모두 다운일 때 순차 검사는 2 + 0.2 + 1 = 3.2초로 BFF의 3초 호출 예산을 넘긴다 → 상세 헬스의 의존 검사는 병렬이어야 하고, 테스트가 그 경계(3초)를 고정했다. 또 Windows 호스트의 `localhost`는 이 드라이버에서 IPv6 시도가 먼저라 타임아웃이 없으면 주소당 130초를 기다린다 — 시험 컨테이너 호스트를 IPv4로 고정하고 연결 타임아웃을 두었다.
- **트레이스에도 로그와 같은 규율이 필요하다.** 계측 라이브러리는 기본으로 URL 속성에 쿼리스트링을 그대로 넣고 몇 가지 클라우드 서명 파라미터만 가린다 — 계약은 로그의 쿼리스트링만 다뤘다. 테스트가 span의 속성·이벤트에 토큰·헤더·쿼리·원문 식별자가 없음을 단언하고 계약에 트레이스 규칙을 더했다.
- **"그대로 신뢰"에는 상한이 있어야 한다.** 상류 요청 id를 그대로 로그와 응답에 되돌리면 외부 클라이언트가 로그 줄 크기와 내용을 통제한다. 형식(문자 집합 · 128자) 안의 값만 쓰고 아니면 새로 만들도록 계약을 보정하고 테스트로 고정했다.
- **해시 필드는 성질로 고정한다.** 사용자 식별자의 해시(`sub_hash`)는 알고리즘을 테스트가 정하지 않고 "16자 이상 hex · 원문과 다름 · 같은 입력에 같은 값 · 다른 입력에 다른 값 · 출력 어디에도 원문 없음"만 단언한다. 구현의 자유를 남기면서 프라이버시 성질은 잠근다.
- **로그 캡처는 전역 설정 1회 + 싱크 비우기.** 구조화 로깅은 프로세스 전역이고 모듈 로거는 첫 사용에 묶인다 — 세션 시작에 한 번 문자열 싱크로 설정하고, 테스트마다 싱크를 비운 뒤 새 줄만 JSON으로 파싱한다. 비-JSON 줄이 섞이면 그것 자체가 실패다("한 줄 = 한 객체").
- **샘플러는 서술 문자열로 비교한다.** 환경변수로 구성된 샘플러가 정확히 "부모 기반 + 비율 0.1"인지는 SDK가 주는 서술 문자열을 같은 클래스로 만든 기대값과 비교하면 된다. 확률적 샘플링을 단언하지 않고, 상류 `traceparent`의 sampled 플래그로 결정적인 두 갈래(수집 1 · 0)를 만든다. 값이 환경에서 오는지는 다른 비율로 한 번 더 구성해 본다.

## 선택과 대안
- **헬스체크 라이브러리 vs `SELECT 1`**: `SELECT 1`. 테이블 허용 목록 충돌과 계약 문면.
- **OTLP 전송**: 연구 메모의 gRPC(4317) 대신 과제 문면의 http(4318). 계약은 둘 다 열어 두었다.
- **로그 싱크**: capsys(표준 출력 가로채기)보다 명시적 스트림 주입 — 로거가 생성 시점의 표준 출력 객체를 붙잡는 함정을 피한다.
- **in-memory exporter + 동기 processor**: 요청이 끝나면 즉시 span을 읽을 수 있다. 배치 processor는 flush 타이밍 문제를 만든다.
- **시험 전용 urlconf**(헬스 라우터 + 로그 뷰 3 + 클레임 헬퍼 미들웨어)를 새 패키지로 두고 지난 과제의 테스트 앱은 그대로 둔다.
- **의존 다운 재현**: 닫힌 포트(시간 초과 경로)와 받자마자 끊는 리스너(수락 수) — 둘 다 쓴다. 전자는 상한 시간을, 후자는 "다이얼했는가"를 증명한다.

## 결과와 검증
- 신규 파일 8(계약 테스트 21케이스 · RFC 9457 단언 헬퍼 · 캐시 연결 수 헬퍼 · 시험 urlconf 패키지 4파일) + 픽스처·설정 덧붙임 + 지난 과제 테스트 1건 수정(연결 수 판정 방식) + 런타임 의존성 6(구조 로그 2 · 추적 3 · API 프레임워크 1) + 잠금 파일(패키지 23 추가) + 러너 기본 옵션(짧은 트레이스백) + 시험 DB 연결 타임아웃.

- 판별력: 저장소 밖 참조 구현(병렬 헬스 · Mapping 마스킹 · URL 속성 정리 · 요청 id 검증으로 확장)에서 21/21(23초 · 세 의존 다운 상세 헬스 2.0초) · 변이 23종(빌더 17 + 컨트롤러 6) 전부 검출 · 출력에 비밀 0 → 참조 구현 삭제.
- 리뷰 2렌즈 approve_with_fixes(medium 4 · low 11) → 결정 14개로 전부 닫음: 테스트 4개 추가(세 의존 동시 다운 · span 속성 누출 · 실제 요청 헤더 매핑 · 요청 id 형식) · 의존 다운 테스트를 수락 수 리스너로 재구성 · docstring 재구성 · 계약 3곳 보정(트레이스 속성 규칙 · 요청 id 형식 · 상세 헬스 3초/병렬) · 규칙 2절 · 러너 기본 옵션 · Windows IPv4 고정.
- 계약 결함·공백 보정: 연구 메모의 헬스체크 라이브러리 미채택(테이블 허용 목록 충돌) · 트레이스 속성 규칙 신설 · 요청 id 신뢰 범위 · 상세 헬스 시간 상한. 설계 커밋이 먼저, 테스트 커밋이 뒤.
- Docker 위생: 컨테이너 잔류 0 · 익명 볼륨 24 → 24. 비밀 스캔 no leaks.

## 사고·오류
- 빌더의 변이 실측 중 PostgreSQL 드라이버 접속 실패의 트레이스백이 일회용 DB 비밀번호를 스크래치 출력에 찍었다(파기된 컨테이너 · 파일 삭제 · 저장소·보고에 없음). 원인은 드라이버의 인자 재바인딩 + 러너의 인자 값 출력 — 지난 과제(테스트 헬퍼 인자)와 같은 계열의 두 번째 사례라 스위트 전역 기본을 바꿨다.
- 컨트롤러가 테스트에 지정한 "연결 목록 id 차집합" 방식이 변이 2종을 놓쳤다 — 빌더가 실측으로 반증하고 더 강한 방식으로 바꿨다. 설계가 틀렸을 때 실측이 이기는 것이 맞다.
- 컨트롤러가 테스트 함수 하나를 편집하다 원본 루프를 중복 삽입한 채 자리표시 함수 두 개를 남겼다(컴파일은 됐으나 쓰레기). 참조 구현 대상 실행에서 `NameError`로 드러나 바로잡았다 — 편집 뒤에는 반드시 실행으로 확인한다. 같은 날 이 학습 로그도 절 순서를 어긋나게 편집해 다시 썼다.
- 빌더가 권한 거부로 스크래치 참조 구현을 지우지 못했다 → 컨트롤러가 검증 뒤 지웠다(우회 없음).
